## 1. 개요

### 1.1 목적

최근 비전 모델은 정해진 클래스만 찾던 방식에서 벗어나, 글자나 예시 이미지로 원하는 대상을 지정하는 **오픈 어휘(open-vocabulary)** 방식으로 바뀌고 있다. 본 보고서는 이 흐름을 대표하는 모델과 실무에서 자주 쓰는 도구 6종의 기능과 실제 활용 사례를 정리하고, PawFeeder AI의 데이터 구축과 기능 확장에 어떻게 쓸 수 있는지 검토한다.

### 1.2 용어

| 용어 | 뜻 |
|---|---|
| 탐지 (Detection) | 물체 위치를 사각형 박스로 찾음 |
| 분할 (Segmentation) | 물체 모양을 픽셀 단위 마스크로 찾음 |
| 프롬프트 (Prompt) | 모델에게 무엇을 찾을지 알려 주는 입력. 텍스트, 예시 박스, 점 등 |
| 제로샷 (Zero-shot) | 해당 클래스를 따로 학습하지 않고 바로 인식 |
| 임베딩 (Embedding) | 이미지나 글을 의미를 담은 숫자 벡터로 바꾼 것 |
| 랜드마크 (Landmark) | 눈, 코, 관절 같은 특징점 좌표 |

## 2. YOLOE

### 2.1 개요

| 항목 | 내용 |
|---|---|
| 개발 | 칭화대 (2025.03, 논문 "YOLOE: Real-Time Seeing Anything") |
| 기반 | YOLOv8 / YOLO11 구조. Ultralytics 패키지에 통합 |
| 작업 | 오픈 어휘 탐지 + 인스턴스 분할 |
| 크기 | s / m / l (예: `yoloe-11s-seg.pt`) |
| 라이선스 | AGPL-3.0 (상용 시 Ultralytics 엔터프라이즈 라이선스 필요) |

### 2.2 주요 기능: 3가지 프롬프트 방식

| 방식 | 입력 | 핵심 기술 | 쓰임 |
|---|---|---|---|
| 텍스트 프롬프트 | `["cat", "dog bowl"]` | RepRTA: 텍스트 임베딩을 가벼운 모듈로 다듬은 뒤 모델에 합쳐 넣어 추론 시 추가 비용 없음 | 찾을 대상의 이름을 알 때 |
| 비주얼 프롬프트 | 예시 물체에 그린 박스 | SAVPE: 박스 영역의 특징을 뽑아 "이것과 같은 것"을 찾음 | 이름으로 설명하기 어려운 대상 |
| 프롬프트 프리 | 없음 | LRPC: 내장 어휘(약 4,500개)와 비교해 보이는 물체를 모두 찾음 | 장면에 무엇이 있는지 훑어볼 때 |

- 텍스트 클래스를 한 번 등록하면 일반 YOLO와 같은 속도로 동작한다.
- 논문 기준 YOLOE-v8-S는 YOLO-Worldv2-S보다 LVIS에서 3.5 AP 높고, 학습 비용은 1/3, 추론은 1.4배 빠르다.
- 일반 YOLO처럼 자체 데이터로 미세조정할 수 있고 ONNX, TensorRT, TFLite 등으로 내보낼 수 있다.

### 2.3 활용 사례

| 분야 | 어디에 쓰이나 | 어떻게 쓰이나 |
|---|---|---|
| 스마트 CCTV | 매장, 공장, 주차장 감시 카메라 | "helmet", "forklift", "fire"처럼 관리자가 글자로 찾을 대상을 바꾸면 재학습 없이 바로 감시 대상 변경 |
| 산업 안전 | 건설 현장, 제조 라인 | 안전모·조끼 미착용자, 위험 구역에 들어간 사람을 실시간 탐지 |
| 로봇 / 피지컬 AI | 물류 로봇, 서비스 로봇, 가정용 로봇 | "빨간 컵을 집어" 같은 명령에서 대상 물체를 찾아 로봇 팔이 집을 위치를 계산 |
| 리테일 | 진열대 관리, 무인 매장 | 신상품을 예시 박스 하나로 등록(비주얼 프롬프트)해 진열 상태·결품 확인 |
| 드론 / 농업 | 작물 모니터링, 시설 점검 | 병든 잎, 균열, 해충 등 이름 붙이기 어려운 대상을 예시 이미지로 찾기 |
| 데이터 라벨링 | AI 학습 데이터 제작 | 새 데이터셋의 1차 박스·마스크를 자동 생성해 사람은 검수만 |

> 예: 배달 로봇이 평소엔 "person, car, bicycle"만 찾다가, 공사 구간에 들어서면 "traffic cone, barrier"를 추가해 바로 인식한다.

### 2.4 장단점

| 장점 | 단점 |
|---|---|
| 실시간, 엣지 배포 가능 | 대형 모델(DINO-X, SAM 3) 대비 정확도 낮음 |
| 재학습 없이 새 클래스 추가 | 드물거나 세밀한 개념(예: "고양이 얼굴의 귀 시작점")에는 약함 |
| Ultralytics 생태계 그대로 사용 (학습, 내보내기) | AGPL 라이선스 |

## 3. DINO-X

### 3.1 개요

| 항목 | 내용 |
|---|---|
| 개발 | IDEA Research (2024.11, 논문 "DINO-X: A Unified Vision Model for Open-World Object Detection and Understanding") |
| 계보 | DINO → Grounding DINO → Grounding DINO 1.5 → DINO-X |
| 학습 데이터 | Grounding-100M (1억 장 이상 규모의 그라운딩 데이터) |
| 버전 | DINO-X Pro (최고 성능, 클라우드), DINO-X Edge (경량, 엣지용) |
| 제공 방식 | 가중치 비공개. DeepDataSpace 클라우드 API로 사용 (유료, 무료 크레딧 있음) |

### 3.2 주요 기능

| 기능 | 설명 |
|---|---|
| 오픈 월드 탐지 | 텍스트, 비주얼, 사용자 정의 프롬프트, 프롬프트 프리 모두 지원 |
| 분할 | 탐지된 물체의 마스크 |
| 키포인트 | 사람 자세, 손, 동물 자세 키포인트 |
| 물체 캡션 | 박스 영역을 문장으로 설명 |
| 영역 질의응답 | 특정 영역에 대한 질문에 답변 (VQA) |

- 논문 기준 제로샷 성능: COCO 56.0 AP, LVIS-minival 59.8 AP, LVIS 희귀 클래스 63.3 AP. 공개 당시 오픈 월드 탐지 최고 수준이었다.
- 희귀하고 긴 꼬리(long-tail) 클래스에 특히 강하다.

### 3.3 활용 사례

| 분야 | 어디에 쓰이나 | 어떻게 쓰이나 |
|---|---|---|
| 자동 라벨링 | 데이터 라벨링 회사, AI 연구소 | 수십만 장의 이미지에 박스·마스크·키포인트를 자동으로 달아 라벨링 비용 절감 (가장 대표적인 쓰임) |
| 자율주행 | 차량 인식 데이터 구축 | 주행 영상에 드물게 나오는 물체(동물, 낙하물, 특수 차량) 찾기 |
| 전자상거래 | 상품 이미지 관리 | 상품 사진 속 물건을 찾아 설명(캡션)을 자동 생성, 카테고리 분류 |
| 스포츠 / 헬스케어 | 경기 분석, 재활 | 사람·동물 자세 키포인트로 움직임 분석 |
| 콘텐츠 검수 | SNS, 플랫폼 | 이미지 속 특정 물체(무기, 담배 등) 검출과 영역 질의응답 |
| 로봇 연구 | 범용 로봇의 인식 모듈 | 처음 보는 물체도 이름으로 찾고 "이것은 무엇인가" 설명 |

> 예: 자율주행 회사가 1년치 주행 영상에서 "도로 위 동물", "떨어진 짐"이 찍힌 장면만 DINO-X로 골라내 희귀 상황 학습 데이터로 쓴다.

### 3.4 장단점

| 장점 | 단점 |
|---|---|
| 오픈 월드 탐지 정확도 최상위권 | 가중치 비공개, 인터넷 연결 필수 |
| 탐지·분할·키포인트·캡션을 한 모델로 | 호출당 비용 발생 |
| 희귀 클래스에 강함 | 데이터를 외부 서버로 보내야 함 (개인정보 고려) |

## 4. SAM 3

### 4.1 개요

| 항목 | 내용 |
|---|---|
| 개발 | Meta (2025.11, "SAM 3: Segment Anything with Concepts") |
| 계보 | SAM (2023, 이미지) → SAM 2 (2024, 영상) → SAM 3 (2025, 개념) |
| 크기 | 약 8.5억(848M) 파라미터 |
| 학습 데이터 | SA-Co 데이터셋 (400만 개 이상의 고유 개념) |
| 제공 방식 | 가중치 공개 (Hugging Face `facebook/sam3`, 접근 승인 필요). Transformers, Ultralytics에서도 사용 가능 |

### 4.2 주요 기능

SAM 1, 2는 점이나 박스로 **물체 하나**를 지정해야 했다. SAM 3는 **개념(Promptable Concept Segmentation, PCS)**을 받아 해당하는 **모든 물체**를 찾는다.

| 프롬프트 | 예 | 결과 |
|---|---|---|
| 짧은 명사구 | "yellow school bus", "striped cat" | 조건에 맞는 모든 물체의 마스크 |
| 예시 이미지 박스 | 고양이 한 마리에 박스 (+/- 지정 가능) | 비슷한 모든 물체 |
| 점, 박스 (SAM 2 방식) | 클릭 한 번 | 해당 물체 하나 |
| 영상 | 위 프롬프트 + 영상 | 프레임마다 분할 + 같은 물체에 같은 ID로 추적 |

- 논문 기준 개념 분할 벤치마크(SA-Co)에서 기존 시스템 대비 약 2배 성능.
- 탐지기와 추적기가 같은 백본을 공유하고, "존재 토큰(presence token)"으로 개념이 이미지에 있는지 먼저 판단해 오탐을 줄인다.

### 4.3 활용 사례

| 분야 | 어디에 쓰이나 | 어떻게 쓰이나 |
|---|---|---|
| 영상 편집 | Instagram Edits 등 Meta 앱 | "사람"을 지정하면 영상 내내 사람만 따라가며 배경 흐림·효과 적용 |
| 쇼핑 / AR | Facebook Marketplace "방에서 보기" | 방 사진에서 가구 영역을 분할해 새 가구를 배치해 보기 |
| 생태·환경 연구 | 야생동물 카메라, 해양 영상 | "zebra", "jellyfish"로 영상 속 모든 개체를 분할·추적해 개체 수 세기 |
| 의료 영상 연구 | 세포, 조직 이미지 | 예시 세포 몇 개를 지정해 같은 종류 세포 전체를 분할 |
| 로봇 / 피지컬 AI | 물체 조작 | 집을 물체의 정확한 윤곽을 구해 잡는 지점 계산 |
| 데이터 라벨링 | 분할 데이터셋 제작 | 탐지 박스 → SAM 3 마스크로 픽셀 단위 정답 자동 생성 |
| 3D | SAM 3D와 연계 | 분할한 물체를 3D 모델로 복원 |

> 예: 축구 경기 영상에 "player in red jersey"를 입력하면 빨간 팀 선수 전원을 경기 내내 ID별로 추적해 이동 거리를 계산한다.

### 4.4 장단점

| 장점 | 단점 |
|---|---|
| 개념 하나로 모든 인스턴스 분할 | 무거움. GPU 필요, 실시간 엣지 실행 어려움 |
| 영상 추적까지 한 모델로 | 긴 문장이나 복잡한 추론은 약함 (짧은 명사구에 최적) |
| 마스크 품질이 매우 높음 | 가중치 사용에 승인 절차 |

## 5. SigLIP 2

### 5.1 개요

| 항목 | 내용 |
|---|---|
| 개발 | Google DeepMind (2025.02) |
| 계보 | CLIP (OpenAI) → SigLIP (2023) → SigLIP 2 |
| 구조 | 이미지 인코더(ViT) + 텍스트 인코더 |
| 크기 | B (약 86M), L (약 303M), So400m (약 400M), g (약 1B) |
| 변형 | 고정 해상도 (예: 224, 384, 512) / NaFlex (원본 비율 유지, 가변 해상도) |
| 제공 방식 | 가중치 공개 (Hugging Face `google/siglip2-*`), Apache-2.0 |

### 5.2 주요 기능

이미지와 텍스트를 **같은 벡터 공간**에 넣어, 의미가 비슷하면 벡터도 가깝게 만든다. 스스로 박스나 마스크를 내지 않으며 다른 모델의 "눈" 역할을 한다.

| 기능 | 설명 |
|---|---|
| 제로샷 분류 | "a photo of a cat", "a photo of a dog" 중 어느 글과 가까운지로 분류 |
| 이미지-텍스트 검색 | 글로 이미지 찾기, 이미지로 글 찾기 |
| 이미지-이미지 유사도 | 중복 사진 제거, 비슷한 사진 묶기 |
| VLM 백본 | PaliGemma 2, Gemma 3 등 멀티모달 LLM의 이미지 인코더로 사용 |

SigLIP 대비 개선점:
- 학습에 캡션 생성(LocCa), 자기 증류, 마스크 예측을 추가해 **위치 정보와 세밀한 특징**이 좋아짐
- **다국어** 데이터로 학습해 한국어 등 여러 언어 텍스트 지원
- CLIP의 소프트맥스 대신 **시그모이드 손실**을 써서 큰 배치 없이도 학습 효율이 좋음

### 5.3 활용 사례

| 분야 | 어디에 쓰이나 | 어떻게 쓰이나 |
|---|---|---|
| 이미지 검색 | 사진 앱, 쇼핑몰, 사내 자료 검색 | "해변에서 노는 강아지"라고 입력하면 해당 사진 찾기. 상품 사진으로 비슷한 상품 찾기 |
| 멀티모달 AI | PaliGemma 2, Gemma 3 등 VLM | 이미지를 LLM이 이해할 수 있는 벡터로 바꾸는 "눈" 역할 |
| 데이터 정제 | AI 학습 데이터 구축 | 수백만 장 중 주제와 무관한 사진, 중복 사진, 저품질 사진 걸러내기 |
| 콘텐츠 분류·검수 | SNS, 광고 플랫폼 | 학습 없이 "폭력적", "음식", "풍경" 등으로 이미지 자동 분류 |
| 로봇 / 피지컬 AI | VLA(시각-언어-행동) 모델 | 로봇이 카메라 장면과 언어 명령을 연결하는 인코더 |
| 추천 시스템 | 패션, 인테리어 | 사용자가 좋아한 이미지와 비슷한 스타일 추천 |

> 예: 쇼핑몰에서 고객이 찍은 신발 사진을 SigLIP 2 임베딩으로 바꿔, 상품 DB에서 가장 가까운 벡터의 상품을 보여준다.

### 5.4 장단점

| 장점 | 단점 |
|---|---|
| 학습 없이 분류, 검색 가능 | 위치(박스, 마스크) 정보 없음 |
| 다국어 지원 | 개체 단위 구분(우리 집 "나비" vs "초코")은 전용 모델보다 약함 |
| 크기 선택 폭이 넓고 라이선스가 자유로움 | 큰 모델은 엣지에서 무거움 |

## 6. OCR (광학 문자 인식)

### 6.1 개요

OCR은 특정 모델 하나가 아니라 **이미지 속 글자를 읽는 기술**이다. 보통 두 단계로 동작한다.

```
이미지 → [글자 영역 탐지] 텍스트 박스 → [글자 인식] 문자열 → (선택) 문서 구조 분석
```

| 도구 | 특징 | 한국어 | 비고 |
|---|---|---|---|
| **PaddleOCR** (Baidu) | 정확도와 속도 균형, 경량 모델(PP-OCR 시리즈), 문서 구조 분석 지원 | 지원 | Apache-2.0, 엣지 배포 쉬움 |
| **EasyOCR** | 설치·사용이 가장 쉬움, 80개 이상 언어 | 지원 | PyTorch 기반 |
| **Tesseract** | 오래된 오픈소스 표준, 깨끗한 인쇄 문서에 적합 | 지원 | 사진 속 글자에는 약함 |
| **VLM 기반 OCR** | 대형 멀티모달 모델로 표, 수식, 손글씨까지 읽음 | 모델마다 다름 | 무겁고 느림 |

### 6.2 주요 기능

- 글자 영역 탐지 (기울어진 글자, 곡선 글자 포함)
- 글자 인식 (인쇄체, 일부 손글씨)
- 문서 방향 보정, 휘어진 문서 펴기
- 표, 제목, 본문 등 레이아웃 분석 (PaddleOCR PP-Structure 등)

### 6.3 활용 사례

| 분야 | 어디에 쓰이나 | 어떻게 쓰이나 |
|---|---|---|
| 금융 / 행정 | 은행 앱 신분증 인증, 세금 서류 | 신분증·통장 사본을 찍으면 이름, 번호 자동 입력 |
| 회계 | 영수증·카드 전표 처리 | 영수증 사진에서 상호, 금액, 날짜를 읽어 경비 자동 정리 |
| 교통 | 주차장, 과속 단속 | 번호판 인식으로 출입 차량 자동 기록 |
| 물류 | 택배 분류 센터 | 송장 주소와 운송장 번호를 읽어 자동 분류 |
| 제조 | 생산 라인 검사 | 제품에 인쇄된 일련번호, 유통기한 인쇄 상태 확인 |
| 번역 / 접근성 | 카메라 번역 앱, 시각장애인 보조 | 간판·메뉴판 글자를 읽어 번역하거나 음성으로 읽어 줌 |
| 문서 디지털화 | 도서관, 기업 문서 | 종이 문서·스캔 PDF를 검색 가능한 텍스트로 변환, RAG 자료로 활용 |

> 예: 아파트 주차장 차단기가 번호판을 OCR로 읽어 등록 차량이면 자동으로 문을 연다.

### 6.4 장단점

| 장점 | 단점 |
|---|---|
| 경량 모델은 엣지에서 실시간 가능 | 흐림, 반사, 기울기에 정확도가 크게 떨어짐 |
| 오픈소스 선택지가 많음 | 손글씨, 특이한 글꼴은 오인식 많음 |
| 별도 학습 없이 바로 사용 | 한국어는 영어보다 정확도가 낮은 편 |

## 7. MediaPipe

### 7.1 개요

| 항목 | 내용 |
|---|---|
| 개발 | Google |
| 성격 | 기기 내(on-device) 실시간 처리를 위한 **완성형 솔루션 모음** |
| 지원 환경 | Python, Android, iOS, Web(JavaScript), Raspberry Pi 등 |
| 모델 형식 | `.task` 파일 (TFLite 기반) |
| 라이선스 | Apache-2.0 |

### 7.2 주요 기능 (MediaPipe Tasks)

| 분야 | 솔루션 | 출력 |
|---|---|---|
| 손 | Hand Landmarker | 손 하나당 21개 3D 랜드마크, 왼손/오른손 |
| 손 | Gesture Recognizer | 주먹, 엄지척, 브이 등 제스처 이름 |
| 얼굴 | Face Detector | 얼굴 박스 + 6개 특징점 |
| 얼굴 | Face Landmarker | 478개 3D 랜드마크, 52개 표정 계수(blendshape) |
| 몸 | Pose Landmarker | 33개 신체 랜드마크 |
| 일반 | Object Detector, Image Classifier, Image Segmenter | 박스, 클래스, 마스크 |
| 기타 | Interactive Segmenter, Image Embedder, 텍스트·오디오 작업 | 각 작업 결과 |

- **사람** 중심 솔루션이 강점이다. 반려동물 얼굴 랜드마크 같은 전용 기능은 없다.
- Model Maker로 분류기, 탐지기, 제스처 인식기를 자체 데이터로 쉽게 재학습할 수 있다.
- 기존 `mp.solutions` API는 지원이 종료되는 중이므로 새 코드는 Tasks API를 쓴다.

### 7.3 활용 사례

| 분야 | 어디에 쓰이나 | 어떻게 쓰이나 |
|---|---|---|
| 피트니스 / 헬스케어 | 홈트레이닝 앱, 재활 운동 | 33개 관절 좌표로 스쿼트 자세 교정, 반복 횟수 자동 카운트 |
| 영상 통화 / SNS | Google Meet 배경 흐림, 카메라 필터 | 사람 영역 분할로 배경 교체, 얼굴 랜드마크로 AR 마스크·메이크업 필터 |
| 제스처 인터페이스 | 키오스크, 스마트 TV, 차량 | 손을 흔들거나 집는 동작으로 화면 넘기기, 비접촉 조작 |
| 수어 인식 | 접근성 서비스 | 손 21개 랜드마크 흐름으로 수어 단어 인식 |
| 운전자 모니터링 | 차량 졸음 감지 | 얼굴 랜드마크로 눈 감김·하품 감지 → 졸음 경고 |
| 아바타 / 메타버스 | VTuber, 3D 캐릭터 | 얼굴 표정 계수로 캐릭터 표정을 실시간으로 따라 하기 |
| 로봇 / 피지컬 AI | 로봇 원격 조작, 모방 학습 | 사람 손 동작을 카메라로 따서 로봇 손에 그대로 전달 |

> 예: 홈트 앱이 스마트폰 카메라만으로 사용자의 무릎 각도를 계산해 "무릎이 발끝을 넘었어요"라고 알려 준다.

### 7.4 장단점

| 장점 | 단점 |
|---|---|
| CPU, 모바일에서도 실시간 | 정해진 작업만 가능 (오픈 어휘 아님) |
| 설치 하나로 바로 사용, 플랫폼 지원 넓음 | 사람 외 대상(동물)은 전용 솔루션 없음 |
| 손, 얼굴 랜드마크 품질이 높음 | 커스터마이징 범위가 Model Maker 수준으로 제한 |

## 9. 본 과제 적용 방안

### 9.1 판단 기준

[PRD.md](../PRD/PRD.md)에서 기기 탑재 모델에 요구하는 조건은 다음과 같다.

| 조건 | 내용 |
|---|---|
| 처리 장치 | RK3566 NPU(0.8 TOPS) 또는 ESP32-S3 |
| 속도 | 15 FPS 이상, 접근부터 토출까지 1.2초 이내 |
| 오프라인 | 네트워크 단절 시에도 기기 단독으로 급여 (Safe-fail) |
| 개체 구분 | 등록 개체 간 구분, 오인식률(FAR) 0.1% 이하 |
| 촬영 환경 | 야간 IR 포함 |
| 제외 범위 | 사료 브랜드 자동 인식, B2C 앱 직접 개발, 클라우드 자동 재학습 |

### 9.2 기기 탑재 모델 대체 검토

| 모델 | 대체 적합 여부 | 이유 |
|---|---|---|
| YOLOE | 부적합 | 얼굴 정렬에 필요한 특징점 5개를 출력하지 않는다. 대상이 개·고양이 얼굴로 고정되어 오픈 어휘가 필요 없다 |
| DINO-X | 부적합 | 클라우드 API라 오프라인 급여 요구를 충족하지 못하고, 네트워크 왕복으로 1.2초 지연 목표가 위험하다 |
| SAM 3 | 부적합 | 약 8.5억 파라미터로 GPU가 필요하며 0.8 TOPS NPU에서 실행할 수 없다 |
| SigLIP 2 | 부적합 | 종(고양이/개) 구분은 잘하지만 같은 종 안의 개체 구분용으로 학습되지 않았다. 이미지 인코더만으로도 MobileFaceNet보다 수십 배 무겁다 |
| OCR | 부적합 | 개체 식별과 관련이 없고, 사료 브랜드 인식은 PRD 제외 범위다 |
| MediaPipe | 부적합 | 사람 전용 솔루션으로 반려동물 얼굴 랜드마크가 없다 |

개체 식별은 "무엇인가"가 아니라 "누구인가"를 묻는 문제다. 사진 몇 장 등록만으로 처음 보는 개체를 비교하도록 학습한 얼굴 인식 모델(ArcFace 계열)이 이 문제에 맞다. 따라서 기기 탑재 모델은 [model.md](model.md)에서 정한 **YOLO11n-pose + MobileFaceNet**을 유지한다.

### 9.3 개발 단계 활용

조사한 모델은 기기 탑재 대신 **학습 데이터 구축과 분석 도구**로 활용한다.

| 단계 | 모델 | 활용 방법 | 기대 효과 |
|---|---|---|---|
| 데이터 수집 | SigLIP 2 | 수집한 사진을 "a photo of a cat face" 등과 비교해 반려동물이 없는 사진, 흐린 사진 걸러내기. 이미지 임베딩으로 중복 사진 제거 | 정제 시간 단축 |
| 1차 라벨링 | DINO-X 또는 YOLOE | "cat face. dog face" 프롬프트로 얼굴 박스 자동 생성 후 사람이 검수 | 박스 라벨링 비용 절감 |
| 마스크 라벨링 | SAM 3 | 배경 제거 증강용 반려동물 마스크 생성 | 증강 다양성 확보 |
| 오인식 분석 | YOLOE (프롬프트 프리) | 오인식 영상에서 주변에 무엇이 찍혔는지 확인 | 실패 원인 분석 |

### 9.4 조사 모델이 적합해지는 조건

제품 조건이 바뀌면 일부 모델이 제품 안으로 들어올 수 있다.

| 조건 변화 | 적합해지는 모델 | 활용 |
|---|---|---|
| 보호소처럼 토끼, 페럿 등 대상 종이 늘어남 | YOLOE | 1단계 앞에 종 확인용으로 두고, 텍스트만 바꿔 새 종 추가. 단, 종별 특징점 모델은 별도 필요 |
| B2B 환경에서 서버와 상시 연결 | SigLIP 2, DINO-X | 서버에서 판정이 애매했던 급여 기록 재분석, 등록 사진 품질(흐림, 얼굴 여부) 검사. 기기 실시간 판정에는 쓰지 않음 |
| 처리 장치를 수십 TOPS급(예: Jetson 계열)으로 상향 | YOLOE, SigLIP 2 | 기기 내 보조 판정. 단, 하드웨어 원가 절감이라는 PRD 방향과 충돌 |

### 9.5 주의사항
- DINO-X는 사진을 외부 서버로 보내므로 사용자 가정 사진에는 쓰지 않고, 공개 데이터셋 라벨링에만 사용한다.
- 자동 라벨은 반드시 사람이 검수한다. 특히 1단계 모델의 특징점 5개(양 눈, 코, 양 귀 시작점)는 어떤 모델도 자동으로 만들어 주지 않으므로 직접 라벨링해야 한다.
- YOLOE를 제품에 넣을 경우 AGPL 라이선스 조건을 검토한다.

## 10. 결론

1. **YOLOE**는 빠르고 가벼운 오픈 어휘 탐지기로, CCTV·로봇처럼 현장 기기에서 바로 돌려야 하는 곳에 쓰인다.
2. **DINO-X**는 탐지 정확도와 기능 폭이 가장 넓어 대량 자동 라벨링에 주로 쓰이지만, API 방식이라 오프라인 제품에는 맞지 않는다.
3. **SAM 3**는 개념 단위로 모든 물체를 정밀하게 분할하고 추적해 영상 편집, 연구, 마스크 라벨링에 쓰인다.
4. **SigLIP 2**는 이미지와 글의 의미를 비교하는 범용 인코더로, 검색·분류·데이터 정제와 멀티모달 AI의 눈으로 쓰인다.
5. **OCR**은 번호판·영수증·문서 등 글자 읽기에, **MediaPipe**는 홈트·영상통화 필터·제스처 등 사람 신체 인식에 특화된 완성형 도구다.

본 과제의 요구사항(0.8 TOPS NPU, 15 FPS, 오프라인 급여, 개체 구분)을 기준으로 검토한 결과, 조사한 모델 중 기기 탑재 모델을 대체하기에 더 적합한 모델은 없었다. 기기 탑재 모델은 기존 계획을 유지하고, 위 모델들은 **데이터 정제(SigLIP 2) → 자동 라벨링(DINO-X, YOLOE, SAM 3) → 사람 검수** 흐름으로 학습 데이터 구축에 활용하는 것을 권장한다.

## 부록 A. 코드 사용 예시

각 모델을 직접 실행해 볼 때 참고할 최소 코드다. 패키지 버전에 따라 사용법이 바뀔 수 있으므로 공식 문서를 함께 확인한다.

### YOLOE

```python
from ultralytics import YOLOE

# 텍스트 프롬프트
model = YOLOE("yoloe-11s-seg.pt")
names = ["cat", "dog", "pet bowl"]
model.set_classes(names, model.get_text_pe(names))
results = model.predict("kitchen.jpg", conf=0.25, save=True)

# 프롬프트 프리
model_pf = YOLOE("yoloe-11s-seg-pf.pt")
results = model_pf.predict("kitchen.jpg")
```

실습 스크립트: [test/yoloe_practice.py](../test/yoloe_practice.py), [test/yoloe_colab.ipynb](../test/yoloe_colab.ipynb)

### DINO-X (클라우드 API)

```python
# pip install dds-cloudapi-sdk
from dds_cloudapi_sdk import Config, Client
from dds_cloudapi_sdk.tasks.v2_task import V2Task

client = Client(Config("YOUR_API_TOKEN"))
image_url = client.upload_file("cat_and_dog.jpg")
task = V2Task(
    api_path="/v2/task/dinox/detection",
    api_body={
        "model": "DINO-X-1.0",
        "image": image_url,
        "prompt": {"type": "text", "text": "cat.dog.pet bowl"},
        "targets": ["bbox", "mask"],
    },
)
client.run_task(task)
for obj in task.result["objects"]:
    print(obj["category"], obj["score"], obj["bbox"])
```

### SAM 3

```python
from PIL import Image
from sam3.model_builder import build_sam3_image_model
from sam3.model.sam3_image_processor import Sam3Processor

processor = Sam3Processor(build_sam3_image_model())
state = processor.set_image(Image.open("living_room.jpg"))
output = processor.set_text_prompt(state=state, prompt="cat")
masks, boxes, scores = output["masks"], output["boxes"], output["scores"]
```

### OCR

```python
# PaddleOCR 3.x
from paddleocr import PaddleOCR
ocr = PaddleOCR(lang="korean")

    res.print()

import easyocr
reader = easyocr.Reader(["ko", "en"])

    print(text, round(conf, 2))
```

### MediaPipe

```python
import mediapipe as mp
from mediapipe.tasks import python
from mediapipe.tasks.python import vision

options = vision.HandLandmarkerOptions(
    base_options=python.BaseOptions(model_asset_path="hand_landmarker.task"),
    num_hands=2,
)
detector = vision.HandLandmarker.create_from_options(options)
result = detector.detect(mp.Image.create_from_file("hand.jpg"))
print(len(result.hand_landmarks), "개의 손 검출")
```
