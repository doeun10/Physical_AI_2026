# 하드웨어 부품 구성 보고서: 반려동물 개체 인식 자동 급식기

- 과제명: 반려동물 개체 인식 자동 급식기 (PawFeeder AI)
- 문서 구분: 하드웨어 부품 구성 보고서
- 작성일: 2026-10-14
- 버전: v1.0

---

## 요약

이 제품은 **카메라로 반려동물의 얼굴을 알아보고, 등록된 개체에게만 정해진 양의 사료를 주는 급식기**입니다. 이를 위해 아래 5개 그룹, 총 15종의 부품을 사용합니다.

| 그룹 | 하는 일 | 들어가는 부품 |
|---|---|---|
| **① 두뇌 (처리 장치)** | AI로 얼굴을 알아보고, 모든 부품에 명령을 내림 | AI 프로세서(RK3566), 제어 MCU(ESP32-S3) |
| **② 눈과 감각 (센서)** | 누가 왔는지, 얼마나 가까운지, 사료가 얼마나 있는지 측정 | 카메라, IR 조명, PIR 센서, ToF 거리 센서, 로드셀과 HX711, 잔량 센서, RTC |
| **③ 손과 발 (구동부)** | 사료를 내보내고 그릇 덮개를 여닫음 | 스텝 모터, 모터 드라이버, 서보 모터 |
| **④ 얼굴 (사용자 인터페이스)** | 사용자에게 상태를 보여주고 입력을 받음 | TFT LCD, 버튼 |
| **⑤ 심장 (전원부)** | 부품마다 필요한 전압을 만들어 공급 | 12V 어댑터, 5V 벅 컨버터, 3.3V 레귤레이터 |

```
반려동물 접근 → [PIR·ToF] 감지 → [카메라·IR 조명] 촬영 → [RK3566] AI 인식
   → [ESP32-S3] 명령 → [서보] 덮개 열기 → [스텝 모터] 사료 토출 → [로드셀] 무게 확인
   → [LCD] 표시 / [Wi-Fi] 서버로 전송
```

- **전원:** 12V 4A 어댑터 1개 (최대 소비 약 34W)
- **주요 통신 방식:** 기기 밖은 Wi-Fi(MQTT), Bluetooth(BLE) / 기기 안은 I2C, SPI, UART, PWM, GPIO, MIPI CSI-2
- **처리 장치:** SBC(RK3566, AI 담당) + MCU(ESP32-S3, 제어 담당)

## 1. 개요

### 1.1 목적

PRD(제품 요구사항 문서)에서 정한 기능을 실제로 구현하려면 어떤 하드웨어 부품이 필요한지 정리합니다. 부품마다 **왜 필요한지**, **어떤 전압과 전류로 동작하는지**, **어떤 방식으로 통신하는지**를 함께 정리합니다.

### 1.2 제품 소개

다견·다묘 가정에서는 일반 급식기를 쓰면 한 마리가 다른 아이의 사료까지 먹거나, 처방식이 엉뚱한 개체에게 가는 문제가 생깁니다. 이 제품은 목걸이 태그 없이 **카메라로 얼굴을 인식**해서 이 문제를 해결합니다.

### 1.3 용어 설명

**전기 관련 용어**

| 용어 | 쉬운 설명 |
|---|---|
| **전압 (V, 볼트)** | 전기를 밀어주는 힘. 부품마다 정해진 전압이 있고, 너무 높으면 고장나고 너무 낮으면 동작하지 않음 |
| **전류 (A, 암페어 / mA, 밀리암페어)** | 실제로 흐르는 전기의 양. 1A = 1,000mA. 모터처럼 힘을 쓰는 부품일수록 많이 필요함 |
| **전력 (W, 와트)** | 전압 × 전류. 어댑터 용량을 정할 때 사용 |
| **레일** | 회로 안에서 같은 전압을 공유하는 전원 라인 (예: 5V 레일) |

**통신 방식 용어**

| 용어 | 쉬운 설명 | 사용 예 |
|---|---|---|
| **GPIO** | 켜짐/꺼짐(1/0) 신호 하나를 주고받는 가장 단순한 핀 | 버튼, PIR 센서 |
| **PWM** | 신호를 빠르게 켰다 껐다 하며 그 비율로 세기나 각도를 전달 | 서보 각도, LED 밝기 |
| **I2C** | 선 2개(SDA, SCL)에 여러 부품을 주소로 구분해 함께 연결하는 방식 | 거리 센서, 시계 |
| **SPI** | I2C보다 빠른 4선 방식. 화면처럼 데이터가 많은 부품에 사용 | LCD |
| **UART** | 두 장치가 TX/RX 선으로 1:1 대화하는 방식 | RK3566 ↔ ESP32-S3 |
| **MIPI CSI-2** | 카메라 영상을 고속으로 보내는 전용 통신 방식 | 카메라 |
| **MQTT** | 인터넷으로 작은 메시지를 주고받는 가벼운 통신 규칙 | 기기 → 서버 |
| **Wi-Fi** | 공유기를 거쳐 인터넷에 연결하는 무선 통신 | 기기 ↔ 서버 |
| **Bluetooth (BLE)** | 가까운 기기끼리 적은 전력으로 연결하는 무선 통신 | 스마트폰 → 기기 (초기 설정) |

### 1.4 문서를 읽을 때 참고할 점

- PRD에는 부품 종류만 있고 구체적인 모델명은 없습니다. 그래서 각 부품마다 **시중에서 쉽게 구할 수 있는 대표 모델**을 하나씩 골랐습니다.
- 전압과 전류는 해당 모델 데이터시트의 일반적인 값입니다. 실제로 제작할 때는 구매한 부품의 데이터시트로 다시 확인해야 합니다.

## 2. 시스템 구성

### 2.1 동작 흐름과 사용 부품

PRD의 사용자 시나리오 순서대로, 각 단계에서 어떤 부품이 일하는지 정리했습니다.

| 단계 | 일어나는 일 | 사용 부품 |
|---|---|---|
| ① 대기 | 아주 적은 전력으로 움직임을 감시 | PIR 센서 |
| ② 접근 감지 | 움직임이 생기면 거리를 재고, 30cm 안이면 다음 단계로 진행 | ToF 거리 센서 |
| ③ 촬영 | 얼굴 촬영. 어두우면 적외선 조명을 켬 | 카메라, IR LED |
| ④ AI 인식 | 등록된 개체인지 판단 (유사도 85% 이상이면 인증) | RK3566 (NPU) |
| ⑤ 덮개 열기 | 인증된 개체면 그릇 덮개를 엶 | ESP32-S3, 서보 모터 |
| ⑥ 사료 토출 | 정해진 양(예: 25g)이 될 때까지 디스펜서를 회전 | 스텝 모터, 모터 드라이버, 로드셀, HX711 |
| ⑦ 섭취량 기록 | 개체가 떠나면 남은 양을 재고 덮개를 닫음 | 로드셀, HX711, 서보 모터 |
| ⑧ 결과 전송·표시 | 서버로 전송하고 화면에 표시 | Wi-Fi, LCD |
| 상시 | 사료통 잔량 확인, 정확한 시각 유지 | 잔량 센서, RTC |

### 2.2 MCU와 SBC

처리 장치는 크게 **MCU**와 **SBC** 두 종류가 있습니다. 둘 다 기기의 두뇌 역할을 하지만, MCU는 **작은 제어용 칩**이고 SBC는 **작은 컴퓨터**입니다.

| 구분 | **MCU** (Micro Controller Unit) | **SBC** (Single Board Computer) |
|---|---|---|
| 한 줄 설명 | CPU, 메모리, 입출력 핀이 칩 하나에 들어간 작은 제어용 칩 | 기판 한 장 위에 CPU, RAM, 저장장치, 네트워크가 모두 있는 작은 컴퓨터 |
| 운영체제 | 없음, 또는 RTOS(가벼운 실시간 OS) | Linux 등 일반 OS |
| 메모리 | KB~수 MB | 1~8GB |
| 전력 | 수십~수백 mA (3.3V) | 0.5~2A 이상 (5V) |
| 부팅 시간 | 1초 미만 | 수십 초 |
| 강점 | **실시간 제어**: 정확한 타이밍, 저전력, 저가 | **고성능 처리**: AI, 영상, 복잡한 프로그램 |
| 약점 | 큰 AI 모델이나 고해상도 영상 처리가 어려움 | OS 때문에 마이크로초 단위 타이밍 제어가 불안정함 |
| 예시 | Arduino, **ESP32-S3**, RP2040, STM32 | Raspberry Pi, Jetson Nano, **RK3566 보드** |

> **용어 참고:** RK3566 자체는 **SoC**(System on Chip, CPU·NPU 등을 하나로 모은 칩)입니다. 이 칩을 RAM, 저장장치와 함께 기판에 올린 것이 SBC입니다. 이 보고서의 **SoM**(System on Module)은 SBC를 작게 만들어 다른 기판에 꽂아 쓰는 모듈 형태입니다.

사람에 비유하면 SBC는 생각하고 판단하는 **뇌**이고, MCU는 반사적으로 빠르게 움직이는 **척수**입니다.

### 2.3 메인 보드 구조: SBC(AI 담당) + MCU(제어 담당)

이 제품은 **MCU와 SBC를 모두** 사용하고, 역할을 나눕니다.

```
┌──────────────────────────┐   UART    ┌──────────────────────────┐
│ [SBC] RK3566 (AI 담당)   │ ◀───────▶ │ [MCU] ESP32-S3 (제어 담당)│
│ · 카메라 영상 처리       │  명령/결과 │ · 모터 구동              │
│ · AI 얼굴 인식 (NPU)     │           │ · 센서 측정              │
│ · Wi-Fi, BLE 통신        │           │ · LCD, 버튼              │
└──────────────────────────┘           └──────────────────────────┘
```

**하나로 하지 않고 나누는 이유**

| 이유 | 설명 |
|---|---|
| AI 성능 | ESP32-S3 같은 MCU에는 AI 전용 가속기(NPU)가 없습니다. 2MP 영상에서 얼굴 검출과 인식 모델 2개를 돌리기에 성능이 부족합니다. RK3566에는 약 0.8 TOPS의 NPU가 있어 여유 있게 처리할 수 있습니다. |
| 카메라 연결 | PRD의 2MP 글로벌 셔터 카메라는 대부분 MIPI CSI-2 방식입니다. ESP32-S3는 이 방식을 지원하지 않고, RK3566은 지원합니다. |
| 제어 정확도 | RK3566은 Linux로 동작해서, 모터 펄스처럼 정확한 타이밍이 필요한 작업에 약합니다. MCU는 이런 실시간 제어에 강합니다. |
| 안전성 | AI 쪽이 재부팅되더라도 MCU가 모터를 안전하게 멈추고 덮개를 닫을 수 있습니다. |

> **원가를 낮추고 싶다면:** ESP32-S3 하나로 AI와 제어를 모두 하는 구성도 가능합니다. 대신 카메라를 DVP 방식(롤링 셔터)으로 바꾸고, AI 입력 해상도를 낮추고, KPI의 "15 FPS"를 "접근 후 1.2초 안에 판정"으로 조정해야 합니다.

## 3. 부품 상세

### 3.1 두뇌: 처리 장치

#### ① AI 프로세서 (SBC): Rockchip RK3566 SoM

| 항목 | 내용 |
|---|---|
| 역할 | 카메라 영상을 받아 AI 모델(얼굴 검출 → 특징 추출 → 비교)을 실행하고, Wi-Fi로 서버와 통신. 처음 설치할 때는 BLE로 스마트폰에서 Wi-Fi 정보를 받음 |
| 전압 | 5V (보드 입력) |
| 전류 | 평상시 약 0.5~1A / 최대 약 2A |
| 통신 | 카메라: MIPI CSI-2 / ESP32-S3: UART / 외부: Wi-Fi 2.4GHz (MQTT over TLS), Bluetooth (BLE, 초기 설정) |
| 없으면 | 얼굴 인식이 불가능해서 제품의 핵심 기능이 사라짐 |

#### ② 제어 MCU: Espressif ESP32-S3-WROOM-1

| 항목 | 내용 |
|---|---|
| 역할 | RK3566의 명령을 받아 모터, 센서, 화면 등 모든 주변 부품을 직접 제어 |
| 전압 | 3.3V |
| 전류 | 평상시 약 40~100mA (이 구조에서는 Wi-Fi를 쓰지 않음) |
| 통신 | RK3566: UART / 주변 부품: I2C, SPI, PWM, GPIO |
| 없으면 | 모터를 정확히 제어할 수 없고, AI 쪽이 멈추면 기기 전체가 멈춤 |

### 3.2 눈과 감각: 센서

#### ③ 카메라: 2MP RGB-IR 글로벌 셔터 센서 (예: OmniVision OG02B 계열)

| 항목 | 내용 |
|---|---|
| 역할 | 반려동물의 얼굴을 촬영. 낮에는 컬러, 밤에는 적외선으로 촬영 |
| 전압 | 2.8V(아날로그) / 1.8V(입출력) / 1.2V(코어). 카메라 모듈 안의 레귤레이터가 만들어 줌 |
| 전류 | 약 100~150mA |
| 통신 | 영상: MIPI CSI-2 / 설정: SCCB (I2C와 같은 방식) |
| 글로벌 셔터를 쓰는 이유 | 화면 전체를 한 번에 찍기 때문에 움직이는 동물의 얼굴이 휘거나 번지지 않음 |

#### ④ IR LED 보조조명: 850nm 적외선 LED + MOSFET

| 항목 | 내용 |
|---|---|
| 역할 | 사람 눈에는 거의 안 보이는 적외선을 비춰 어두운 곳에서도 촬영할 수 있게 함 |
| 전압 | 5V (MOSFET 스위치를 거쳐 공급) |
| 전류 | 꺼짐 0 / 켜짐 약 200~300mA |
| 통신 | PWM (밝기 조절) |
| 없으면 | 밤에 얼굴 인식이 실패함. KPI의 "야간 조명 포함 정확도 98.5%"를 달성할 수 없음 |

#### ⑤ PIR 인체감지 센서: AM312

| 항목 | 내용 |
|---|---|
| 역할 | 동물의 체온(적외선) 변화로 움직임을 감지해 시스템을 깨움 |
| 전압 | 2.7~12V (3.3V로 사용) |
| 전류 | 약 15µA (0.015mA) |
| 통신 | GPIO (감지되면 High 출력) |
| 필요한 이유 | 거리 센서나 카메라보다 수천 배 적은 전력으로 24시간 감시할 수 있음. 평소에는 나머지 부품을 쉬게 해서 전력과 발열을 줄임 |

#### ⑥ ToF 거리 센서: ST VL53L1X

| 항목 | 내용 |
|---|---|
| 역할 | 빛이 물체에 닿았다 돌아오는 시간으로 거리를 잼 (최대 4m) |
| 전압 | 2.6~3.5V (3.3V로 사용) |
| 전류 | 측정 중 약 16~20mA / 대기 수 µA |
| 통신 | I2C + XSHUT 핀(켜고 끄기), INT 핀(측정 완료 알림) |
| 필요한 이유 | PIR은 "움직임이 있다"만 알고 거리는 모름. ToF로 **30cm 안에 들어왔을 때만** 카메라를 켜서, 지나가는 동물에 반응하는 것을 막음 |

#### ⑦ 로드셀: 3kg 빔형 로드셀

| 항목 | 내용 |
|---|---|
| 역할 | 그릇의 무게를 잼. 무게가 실리면 금속이 아주 조금 휘고, 그 변화를 전기 신호로 바꿈 |
| 전압 | 여기전압 3.3~5V (HX711이 공급) |
| 전류 | 약 3~5mA |
| 통신 | 아날로그 신호 (수 mV 수준) → HX711로 전달 |
| 필요한 이유 | ① 목표량(예: 25g)만큼 나왔는지 확인 ② 실제 섭취량(지급량 − 잔여량) 계산. 이 제품의 핵심인 **개체별 섭취 기록**에 꼭 필요함 |

#### ⑧ 로드셀 증폭·변환기: Avia HX711

| 항목 | 내용 |
|---|---|
| 역할 | 로드셀의 아주 작은 신호를 증폭해 24bit 디지털 값으로 바꿈 |
| 전압 | 2.6~5.5V (아날로그 쪽 5V, 디지털 쪽 3.3V로 사용) |
| 전류 | 약 1.5mA 미만 |
| 통신 | 2선 시리얼 (PD_SCK, DOUT). I2C가 아닌 HX711만의 방식 |
| 필요한 이유 | 로드셀 신호는 너무 작아서 MCU에 직접 연결하면 g 단위 측정이 불가능함 |

#### ⑨ 사료 잔량 센서: ST VL53L0X

| 항목 | 내용 |
|---|---|
| 역할 | 사료통 위에서 사료 표면까지의 거리를 재서 남은 양을 추정 |
| 전압 | 2.6~3.5V (3.3V로 사용) |
| 전류 | 측정 중 약 19mA |
| 통신 | I2C + XSHUT 핀 |
| 필요한 이유 | 사료통이 비기 전에 "사료 부족" 알림을 보냄 (PRD 개발 범위 4번) |

#### ⑩ 실시간 시계(RTC): Maxim DS3231 + 코인 전지

| 항목 | 내용 |
|---|---|
| 역할 | 전원이나 인터넷이 끊겨도 현재 시각을 계속 유지 |
| 전압 | 2.3~5.5V (3.3V로 사용, 정전 시 CR2032 전지로 유지) |
| 전류 | 약 200µA |
| 통신 | I2C |
| 필요한 이유 | PRD의 **오프라인 급여 모드**. 인터넷 시간을 받을 수 없어도 정해진 시각에 급여해야 함 |

### 3.3 손과 발: 구동부

#### ⑪ 스텝 모터: NEMA17 (17HS4401급)

| 항목 | 내용 |
|---|---|
| 역할 | 사료통 아래의 디스펜서(나선형 스크루)를 회전시켜 사료를 내보냄 |
| 전압 | 12V (드라이버를 거쳐 구동) |
| 전류 | 구동 시 상당 약 1.0~1.7A / 정지 시 거의 0 |
| 통신 | 직접 통신하지 않음. 드라이버가 구동 |
| 회전하는 이유 | 출구만 열면 중력 때문에 사료가 한꺼번에 쏟아짐. 스크루가 한 바퀴 돌 때마다 일정한 양만 밀어내므로 **회전 각도로 사료량을 조절**할 수 있음 |
| 스텝 모터를 쓰는 이유 | "몇 도 돌아라"를 정확히 지시할 수 있음. 일반 DC 모터는 얼마나 돌았는지 알기 어려움 |

```
      ┌─────────┐
      │ 사료통  │
      │ ○○○○○○ │
      └───┬─────┘
   모터 ─▶│ ⌇⌇⌇⌇ │ ◀ 나선형 스크루 (회전할 때마다 일정량 이동)
          └──┬───┘
             ▼ 사료
          ┌──────┐
          │ 그릇 │ ◀ 아래에 로드셀
          └──────┘
```

#### ⑫ 스텝 모터 드라이버: Trinamic TMC2209

| 항목 | 내용 |
|---|---|
| 역할 | MCU의 약한 신호(3.3V, 수 mA)를 모터를 돌릴 큰 전류(12V, 1A 이상)로 바꿔줌 |
| 전압 | 모터 쪽 4.75~29V (12V 사용) / 로직 쪽 3.3~5V |
| 전류 | 최대 2A RMS |

#### ⑬ 서보 모터: TowerPro MG90S (메탈 기어)

| 항목 | 내용 |

| 필요한 이유 | 디스펜서는 사료를 **내보내는** 장치이고, 덮개는 **다른 개체가 먹는 것을 막는** 장치임. A가 먹다 남기고 떠났을 때 B가 와서 먹지 못하도록 인증된 개체가 있을 때만 엶 |

## 5. 전원 설계

### 5.1 전원 계통도

```
 AC 220V
    │
 [12V 4A 어댑터] ── [PTC 퓨즈 · 역전압 방지]
    │
    ├── 12V 레일 ──────────────▶ TMC2209 → 스텝 모터
    │
    └── [벅 컨버터 12V→5V 5A]
           │
           ├── 5V 레일 ────────▶ RK3566(+카메라), 서보, IR LED, HX711(+로드셀)
           │
           └── [LDO 5V→3.3V 1A]
                  │
                  └── 3.3V 레일 ▶ ESP32-S3, VL53L1X, VL53L0X, PIR, DS3231, LCD
```

### 5.2 최대 소비 전력 계산

모든 부품이 동시에 최대 전류를 쓰는 **가장 나쁜 경우**로 계산했습니다.

| 레일 | 부품별 최대 전류 | 합계 전류 | 전력 |
|---|---|---|---|
| 12V | 스텝 모터 1.5A | 1.5A | 18.0W |
| 5V | RK3566 2A, 서보 0.7A, IR LED 0.3A, HX711·로드셀 0.01A | 약 3.0A | 15.0W |
| 3.3V | ESP32-S3 0.25A, LCD 0.05A, ToF 2개 0.04A, 기타 0.01A | 약 0.35A | 1.2W |
| **합계** | | | **약 34W** |

- 어댑터는 계산값보다 약 40% 여유를 두어 **12V 4A(48W)**로 정했습니다.
- 5V 레일 최대 3.0A에 여유를 두어 벅 컨버터는 **5A급**으로 정했습니다.
- 3.3V 레일 최대 0.35A이므로 1A LDO로 충분합니다.

### 5.3 전력을 아끼는 동작 순서

1. 평소에는 **PIR만** 켜져 있고, 카메라·IR LED·LCD 백라이트는 꺼져 있습니다.
2. 서보(덮개 열기)와 스텝 모터(토출)는 **동시에 돌리지 않고 순서대로** 돌려 최대 전류를 낮춥니다.
3. 스텝 모터는 회전하지 않을 때 드라이버 전류를 줄여 발열을 막습니다.

```
 ══════════════════════════ 기기 밖 ══════════════════════════

   ┌───────────────┐                      ┌──────────────────┐
```

| 표시 | 뜻 |
|---|---|
| `[SBC]`, `[MCU]` | 처리 장치. SBC는 판단(AI), MCU는 실행(제어)을 맡음 |
| `─▶` | 데이터나 명령이 흐르는 방향 |
| 선 위의 글자 | 그 구간에서 쓰는 통신 방식 |
| ①②③ | 처리 장치끼리, 또는 기기 밖과 연결되는 주요 통신 구간 |

| 구간 | 통신 방식 | 종류 | 오가는 데이터 |
|---|---|---|---|
| ① 스마트폰 ↔ RK3566 | Bluetooth (BLE) | 무선, 근거리 | Wi-Fi 설정값 (처음 한 번) |
| ② RK3566 ↔ 서버 | Wi-Fi + MQTT | 무선, 인터넷 | 섭취 기록, 알림, 펌웨어 업데이트 |
| ③ RK3566 ↔ ESP32-S3 | UART | 유선, 칩 사이 | 급여 명령과 결과 |
| 카메라 → RK3566 | MIPI CSI-2 / SCCB | 유선, 고속 | 얼굴 영상 |
| ESP32-S3 ↔ 센서 | I2C, GPIO, 2선 시리얼 | 유선, 기판 안 | 거리, 무게, 시각, 움직임 |
| ESP32-S3 → 구동부·화면 | STEP/DIR, PWM, SPI | 유선, 기판 안 | 모터 회전, 덮개 각도, 화면 |

### 6.2 기기 밖 통신 방식 비교

기기 밖과 연결할 때 쓸 수 있는 대표 통신 방식 4가지를 비교하고, 이 제품에서 어떤 것을 쓰는지 정리했습니다.

| 구분 | **Wi-Fi** | **Bluetooth (BLE)** | **ESP-NOW** | **Ethernet** |
|---|---|---|---|---|
| 연결 방식 | 무선, 공유기 필요 | 무선, 기기끼리 1:1 | 무선, 공유기 없이 ESP 기기끼리 직접 | 유선 (LAN 케이블) |
| 속도 | 수십~수백 Mbps | 약 1~2 Mbps | 약 1 Mbps (한 번에 250바이트) | 100 Mbps~1 Gbps |
| 거리 | 실내 약 30~50m | 약 10m | 시야가 트인 실외에서 약 100m 이상 | 케이블 최대 100m |
| 전력 | 높음 | 매우 낮음 | 낮음 | 중간 |
| 인터넷 | 바로 연결됨 | 안 됨 (폰을 거쳐야 함) | 안 됨 | 바로 연결됨 |
| 대표 용도 | 스마트홈 기기, CCTV | 무선 이어폰, 스마트워치, 기기 초기 설정 | ESP 센서끼리 데이터 주고받기 | 데스크톱, 서버, 공장 장비 |
| **이 제품** | ✅ **사용** | ✅ **사용** | ❌ 미사용 (확장용) | ❌ 미사용 |
| **이유** | 가정마다 공유기가 있고 서버와 직접 통신할 수 있음 | 화면이나 키보드 없이도 폰으로 쉽게 Wi-Fi를 설정할 수 있음 | 지금은 기기가 하나라 필요 없음. 나중에 급수기나 체중계를 추가하면 활용 가능 | 바닥에 두는 제품이라 케이블이 걸리적거리고 반려동물이 씹을 위험이 있음 |

> **ESP-NOW란?** ESP32를 만든 Espressif사의 자체 무선 통신 규칙입니다. 칩 이름이 아니라 **ESP 칩끼리 쓰는 통신 방식**이며, 공유기 없이 기기끼리 짧은 메시지를 빠르게 주고받습니다.

> ESP32-S3에도 Wi-Fi와 BLE가 들어 있지만, 이 구조에서는 무선 통신을 RK3566이 맡으므로 꺼 둡니다. 원가를 줄이려고 ESP32-S3 하나만 쓰는 구성으로 바꾸면 ESP32-S3의 Wi-Fi와 BLE를 그대로 사용합니다.

### 6.3 기기 안 통신 방식 정리

| 통신 방식 | 연결 부품 | 사용하는 선 | 고른 이유 |
|---|---|---|---|
| MIPI CSI-2 | 카메라 | 데이터 2쌍 + 클럭 1쌍 | 2MP 영상을 빠르게 전송 |
| UART | RK3566 ↔ ESP32-S3 | TX, RX | 두 칩 사이 1:1 명령 전달에 간단함 |
| I2C | VL53L1X, VL53L0X, DS3231 | SDA, SCL (2선) | 선 2개로 센서 여러 개를 연결 |
| SPI | TFT LCD | SCK, MOSI, CS, DC | 화면 데이터를 빠르게 전송 |
| 2선 시리얼 | HX711 | PD_SCK, DOUT | HX711 전용 방식 |
| STEP/DIR | TMC2209 | STEP, DIR, EN | 펄스 수로 회전 각도를 정확히 지정 |
| PWM | 서보, IR LED, LCD 백라이트 | 신호선 1개 | 각도와 밝기를 간단히 조절 |
| GPIO | PIR, 버튼, TMC2209 DIAG | 신호선 1개 | 켜짐/꺼짐만 알리면 됨 |

### 6.4 I2C 주소

같은 I2C 선에 연결된 부품은 **주소가 서로 달라야** 합니다.

| 부품 | 기본 주소 | 사용할 주소 | 비고 |
|---|---|---|---|
| VL53L1X | 0x29 | **0x30으로 변경** | 기본 주소가 VL53L0X와 같아서 바꿔야 함 |
| VL53L0X | 0x29 | 0x29 | – |
| DS3231 | 0x68 | 0x68 | – |

### 6.5 ESP32-S3 핀 사용량

| 용도 | 핀 수 |
|---|---|
| I2C (SDA, SCL) | 2 |
| ToF 제어 (XSHUT 2, INT 1) | 3 |
| PIR, 버튼 | 2 |
| HX711 | 2 |
| TMC2209 (STEP, DIR, EN, UART, DIAG) | 5 |
| 서보, IR LED | 2 |
| LCD (SCK, MOSI, CS, DC, RST, 백라이트) | 6 |
| RK3566 연결 UART | 2 |
| **합계** | **24** |

ESP32-S3-WROOM-1에서 쓸 수 있는 핀 수 안에 들어갑니다. 다만 PSRAM 내장 모델(N16R8)은 일부 핀을 내부에서 쓰므로 회로를 그릴 때 핀 배치를 확인해야 합니다.

## 7. 설계 시 주의사항

| 주의할 점 | 문제 | 해결 방법 |
|---|---|---|
| I2C 주소 충돌 | VL53L1X와 VL53L0X의 기본 주소가 둘 다 0x29 | 전원을 켤 때 XSHUT 핀으로 하나씩 켜면서 주소를 바꿈 |
| 모터 노이즈 | 모터가 돌 때 생기는 전기 잡음 때문에 로드셀 측정값이 흔들림 | 모터 GND와 로직 GND를 한 점에서만 연결. 12V 입력에 470µF 이상 커패시터. 무게는 모터가 멈춘 뒤 측정 |
| 서보 전압 강하 | 서보가 순간적으로 큰 전류를 쓰면 5V가 떨어져 다른 부품이 재부팅될 수 있음 | 서보 전원선 근처에 100~470µF 커패시터 추가 |
| 전압 레벨 | HX711을 5V로 쓰면 출력 신호도 5V라 ESP32-S3(3.3V)에 무리가 갈 수 있음 | HX711 디지털 쪽 전원(VCC)은 3.3V로 연결 |
| 발열 | RK3566과 벅 컨버터에서 열이 남 | 방열판을 달고, 사료통과 떨어진 곳에 배치 |
| 사료 가루 | 사료 가루가 센서 창이나 기판에 쌓임 | 센서 앞에 투명 커버, 기판은 사료 경로와 분리 |

## 8. 검토 과정에서 변경한 사항

| 변경 | 처음 구성 | 바뀐 구성 | 이유 |
|---|---|---|---|
| 처리 장치 | ESP32-S3 또는 RK3566 중 하나 | RK3566(AI) + ESP32-S3(제어) | MCU 단독으로는 AI 성능이 부족하고 MIPI 카메라를 연결할 수 없음 |
| 초기 설정 | 없음 | **BLE로 스마트폰에서 Wi-Fi 설정** | 화면과 키보드 없이도 사용자가 쉽게 Wi-Fi에 연결할 수 있음 |
| 상태 표시 | RGB 상태 LED | **TFT LCD + 버튼** | LED 색으로는 정보 전달에 한계가 있음. 글자로 섭취량, 오류 등을 바로 확인 가능 |
| 소리 | 스피커 + 앰프 | **삭제** | PRD에서도 핵심 기능이 아님. 경고음이 오히려 급식기에 대한 거부감을 줄 수 있음 |
| 도어 용도 | 사료 출구 도어 | **그릇 덮개** | 출구는 디스펜서가 이미 막고 있음. 덮개가 있어야 다른 개체가 남은 사료를 먹는 것을 막을 수 있음 |
| 전원 용량 | 12V 3A | **12V 4A** | RK3566이 추가되면서 최대 소비 전력이 늘어남 |

## 9. 결론

1. 이 제품은 **총 15종의 부품**으로 구성됩니다. 처리 장치 2종, 센서 8종, 구동부 3종, 사용자 인터페이스 2종이며, 여기에 전원부가 더해집니다.
2. 처리 장치는 **AI는 RK3566, 실시간 제어는 ESP32-S3**로 나눴습니다. 이렇게 해서 AI 성능과 정확한 모터 제어를 모두 확보했습니다.
3. 사료는 **스텝 모터로 정량을 내보내고, 로드셀로 실제 무게를 확인**합니다. 이 두 부품의 조합으로 "정해진 양을 주고, 실제로 얼마나 먹었는지 기록하는" 핵심 기능을 구현합니다.
4. 전원은 **12V 하나를 받아 5V와 3.3V로 나눠** 쓰고, 최대 약 34W에 맞춰 12V 4A 어댑터를 사용합니다.
5. 부품 사이의 통신은 용도에 맞게 나눴습니다. 센서는 **I2C**, 화면은 **SPI**, 모터는 **PWM·STEP/DIR**, 두 칩 사이는 **UART**, 서버와는 **Wi-Fi(MQTT)**, 스마트폰과는 초기 설정 때 **Bluetooth(BLE)**를 씁니다. 전체 연결 관계는 6.1절의 부품 관계도에 정리했습니다.
