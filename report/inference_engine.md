## 1. 개요

### 1.1 목적

학습한 AI 모델을 급식기 안에서 실행하려면 **추론 엔진**이 필요합니다. 후보 4종(ONNX Runtime, NCNN, OpenVINO, TFLite)을 이 제품의 하드웨어와 모델에 맞춰 비교하고, 하나를 선택합니다.

### 1.2 용어

| 용어 | 쉬운 설명 |
|---|---|
| **추론 엔진** | 학습이 끝난 AI 모델 파일을 읽어서 실제 기기에서 계산(추론)을 실행하는 프로그램 |
| **추론** | 새 사진을 넣었을 때 모델이 "누구인지" 답을 내는 과정 |
| **INT8 양자화** | 모델의 숫자를 32비트 실수에서 8비트 정수로 줄이는 것. 속도가 빨라지고 용량이 약 1/4로 줄어듦 |
| **NPU** | AI 계산 전용 칩. RK3566에는 약 0.8 TOPS의 NPU가 있음 |
| **Vulkan** | GPU에게 계산을 시키는 표준 방식. RK3566의 Mali-G52 GPU가 지원함 |

### 1.3 이 제품의 조건

| 항목 | 내용 | 출처 |
|---|---|---|
| AI 처리 장치 | Rockchip RK3566: ARM Cortex-A55 4코어, Mali-G52 GPU, NPU 약 0.8 TOPS | 하드웨어 부품 보고서 |
| 운영체제 | Linux (Android 아님) | 하드웨어 부품 보고서 |
| 1단계 모델 | YOLO11n-pose (얼굴 검출 + 특징점 5개, 입력 320×320) | 모델 설계 보고서 |
| 2단계 모델 | MobileFaceNet (얼굴 특징 벡터 추출, 입력 112×112) | 모델 설계 보고서 |
| 학습 환경 | PyTorch (Ultralytics) | 모델 설계 보고서 |
| 성능 목표 | 15 FPS 이상, 접근 후 1.2초 안에 판정 | PRD |
| 오프라인 | 인터넷이 끊겨도 기기 안에서 인식 | PRD |

## 3. 추론 엔진별 분석

### 3.1 ONNX Runtime

| 항목 | 내용 |
|---|---|
| 만든 곳 | Microsoft |
| 특징 | ONNX 형식 모델을 거의 모든 기기에서 실행하는 범용 엔진. 기기별 가속 모듈(Execution Provider)을 붙여 씀 |
| 장점 | PyTorch에서 ONNX로 바로 내보낼 수 있어 변환이 가장 쉬움. PC에서 같은 파일로 결과를 검증하기 좋음 |
| 단점 | RK3566에서는 CPU로만 실행됨. 예전 Rockchip NPU용 모듈은 이전 세대 칩용이라 RK3566에 쓸 수 없음. 라이브러리가 수십 MB로 무거움 |
| 이 제품에서 | 변환과 검증 단계의 **중간 형식(ONNX)**으로는 유용하지만, 기기 안 실행 엔진으로는 불리함 |

### 3.2 NCNN

| 항목 | 내용 |
|---|---|
| 만든 곳 | Tencent (오픈소스) |
| 특징 | 휴대폰, ARM 보드용으로 만든 경량 추론 엔진. 외부 라이브러리 의존성이 없음 |
| 장점 | ARM CPU 명령(NEON)에 맞춰 최적화되어 있음. Vulkan으로 Mali GPU도 사용 가능. Ultralytics에서 YOLO 모델을 NCNN 형식으로 바로 내보낼 수 있음. INT8 양자화 도구를 기본 제공 |
| 단점 | NPU는 쓰지 못함. ONNX Runtime보다 지원 연산 종류가 적어 변환 후 결과 확인이 필요함 |
| 이 제품에서 | RK3566의 CPU와 GPU를 모두 활용할 수 있고, YOLO와 MobileFaceNet 사용 사례가 많음 |

### 3.3 OpenVINO

| 항목 | 내용 |
|---|---|
| 만든 곳 | Intel |
| 특징 | Intel CPU, 내장 GPU, Intel NPU에 맞춰 최적화된 엔진 |
| 장점 | Intel 기기에서는 매우 빠름. 양자화 도구가 잘 갖춰져 있음 |
| 단점 | 최적화의 중심이 Intel 칩임. ARM CPU도 지원하지만 Mali GPU와 Rockchip NPU는 사용할 수 없음 |
| 이 제품에서 | Intel 칩을 쓰지 않으므로 장점을 살릴 수 없음 |

### 3.4 TFLite (LiteRT)

| 항목 | 내용 |
|---|---|
| 만든 곳 | Google (2024년 LiteRT로 이름 변경) |
| 특징 | 휴대폰, 임베디드 기기용 경량 엔진. MCU용 버전(TFLite Micro)도 있음 |
| 장점 | 가볍고 자료가 많음. CPU 가속(XNNPACK), GPU 가속 모듈을 지원 |
| 단점 | PyTorch 모델을 TFLite로 바꾸는 단계가 추가되어 변환 오류가 생기기 쉬움. NPU 가속 모듈(NNAPI)은 Android 전용이라 Linux에서는 쓸 수 없음 |
| 이 제품에서 | PRD는 처음에 ESP32-S3 단독 구성을 전제로 TFLite Micro를 적었음. AI를 RK3566(Linux)에서 실행하기로 바뀌면서 장점이 줄어듦 |

## 4. 비교 평가

### 4.1 항목별 비교

| 항목 | ONNX Runtime | **NCNN** | OpenVINO | TFLite (LiteRT) |
|---|---|---|---|---|
| ARM CPU 최적화 | 보통 | **강함 (NEON)** | 보통 | 강함 (XNNPACK) |
| Mali GPU 사용 | 불가 | **가능 (Vulkan)** | 불가 | 가능 (OpenCL) |
| Rockchip NPU 사용 | 불가 | 불가 | 불가 | 불가 (Linux) |
| PyTorch 모델 변환 | 매우 쉬움 | **쉬움 (Ultralytics 직접 지원)** | 쉬움 | 어려움 (변환 단계 추가) |
| 라이브러리 용량 | 수십 MB | **수 MB 이하** | 수십 MB | 수 MB |
| INT8 양자화 | 지원 | **지원 (도구 기본 제공)** | 지원 | 지원 |
| 주 사용처 | 서버, PC, 범용 | **휴대폰, ARM 보드** | Intel PC, 서버 | 휴대폰, MCU |

### 4.2 점수 (5점 만점 × 비중 → 100점 환산)

| 기준 (비중) | ONNX Runtime | **NCNN** | OpenVINO | TFLite |
|---|---|---|---|---|
| 하드웨어 지원 (30%) | 3 | **5** | 1 | 3 |
| 속도 (25%) | 3 | **5** | 2 | 3 |
| 모델 변환 편의 (20%) | 5 | **4** | 4 | 2 |
| 가벼움 (15%) | 2 | **5** | 2 | 4 |
| 자료와 사례 (10%) | 5 | **4** | 4 | 5 |
| **합계** | **69** | **94** | **46** | **63** |

점수는 각 엔진의 공식 지원 범위와 일반적으로 알려진 ARM 보드 사용 사례를 바탕으로 매겼습니다. 실제 RK3566 보드에서 측정한 값은 아닙니다.

## 5. 선정 결과: NCNN

### 5.1 선택 이유

1. **RK3566 하드웨어에 가장 잘 맞습니다.** RK3566의 ARM CPU 4코어(NEON)와 Mali GPU(Vulkan)를 모두 쓸 수 있는 엔진은 후보 중 NCNN뿐입니다.
2. **모델 옮기기가 쉽습니다.** 1단계 모델 YOLO11n-pose는 Ultralytics에서 NCNN 형식으로 바로 내보낼 수 있습니다. 2단계 MobileFaceNet도 NCNN으로 변환한 사례가 많습니다.
3. **가볍습니다.** 외부 라이브러리 없이 수 MB 이하로 동작합니다. 그래서 급식기처럼 메모리와 저장 공간이 작은 기기에 넣기 좋습니다.
4. **오프라인으로 동작합니다.** 인터넷 없이 기기 안에서 추론이 끝나므로, PRD의 오프라인 급여 모드를 만족합니다.

### 5.2 다른 후보를 고르지 않은 이유

| 후보 | 고르지 않은 이유 |
|---|---|
| ONNX Runtime | RK3566에서는 CPU만 쓰고 무거움. 대신 변환 중간 단계의 형식(ONNX)으로는 활용함 |
| TFLite (LiteRT) | PyTorch → TFLite 변환 단계가 추가되고, Linux에서는 NPU 가속을 쓸 수 없음 |
| OpenVINO | Intel 칩 전용 최적화라 ARM 기반 RK3566에서 장점이 없음 |

## 6. 적용 계획

### 6.1 변환 과정

```
① PyTorch 학습 (.pt)
② NCNN 형식으로 내보내기 (.param + .bin)
   · YOLO11n-pose: Ultralytics export (format=ncnn)
   · MobileFaceNet: PyTorch → ONNX → NCNN 변환
③ INT8 양자화 (주간·야간·역광 사진을 보정 데이터로 사용)
④ RK3566에서 실행 (CPU 4코어 + Vulkan GPU)
⑤ PC 결과와 비교해 정확도 하락이 1%p 이내인지 확인
```

### 6.2 확인할 성능 목표

| 항목 | 목표 |
|---|---|
| 1단계 YOLO11n-pose (320×320, INT8) | 1장당 약 50ms 이하 |
| 2단계 MobileFaceNet (112×112, INT8) | 1장당 약 15ms 이하 |
| 전체 처리 속도 | 15 FPS 이상 |
| INT8 양자화 후 정확도 하락 | 1%p 이내 |

위 처리 시간은 목표치이며, 실제 보드에서 측정해서 확인해야 합니다.

## 7. 고려사항

| 항목 | 내용 | 대응 |
|---|---|---|
| NPU를 쓰지 못함 | 후보 4종 모두 RK3566의 NPU를 직접 쓰지 못함 | 실측 결과 15 FPS에 못 미치면 Rockchip 전용 도구(RKNN)로 NPU 가속을 추가하는 방안을 검토 |
| 변환 후 결과 차이 | 엔진마다 계산 방식이 조금씩 달라 결과가 달라질 수 있음 | 같은 사진으로 PC(PyTorch)와 기기(NCNN)의 출력을 비교 |
| GPU 발열 | Vulkan GPU를 계속 쓰면 열이 남 | 반려동물이 30cm 안에 접근했을 때만 추론 실행 |
| 기존 문서와의 관계 | 모델 설계 보고서는 RKNN 실행 엔진을 제안했음 | RKNN은 이번 후보에 없는 Rockchip 전용 도구임. NCNN을 기본 엔진으로 하고, RKNN은 성능이 부족할 때 쓰는 선택지로 둠 |

## 8. 결론

1. 후보 4종 중 **NCNN**을 추론 엔진으로 선택합니다 (94점).
2. 선택 이유는 **RK3566의 ARM CPU와 Mali GPU를 모두 활용**할 수 있고, **YOLO 모델을 바로 옮길 수 있으며**, **가볍기** 때문입니다.
3. ONNX는 변환 중간 단계에서만 활용합니다. OpenVINO는 Intel 전용 최적화라서, TFLite는 변환 단계 추가와 Linux NPU 미지원 때문에 제외했습니다.
4. 실제 보드에서 15 FPS를 확인하고, 부족하면 RKNN으로 NPU 가속을 추가합니다.
