## 1. 개요

### 1.1 목적

본 보고서는 반려동물 개체 인식 자동 급식기에 탑재할 AI 모델의 선정 근거와 학습 및 검증 방법을 정리한다. 모델 선정은 제품 요구사항, 현장 환경 조사 결과, 대상 하드웨어의 연산 제약을 근거로 한다.

### 1.2 범위

- 카메라 영상에서 반려동물 얼굴을 검출하고 특징점을 추출하는 모델
- 검출된 얼굴로 개체를 식별하는 모델
- 두 모델의 학습 데이터 구성, 학습 방법, 엣지 기기 배포를 위한 양자화
- 오프라인, 기기, 현장 단계의 검증 방법

후처리(다중 프레임 판정 등)는 본 보고서의 범위에서 제외하며 별도 문서에서 다룬다.

## 2. 요구사항 분석

### 2.1 기능 요구사항

PRD의 사용자 시나리오에서 모델에 요구되는 기능은 다음과 같다.

| 번호 | 요구사항 | PRD 근거 |
|---|---|---|
| F1 | 영상에서 반려동물 얼굴 위치를 검출한다 | 시나리오 3 |
| F2 | 얼굴 특징점(Keypoint)을 추출한다 | 시나리오 3 |
| F3 | 등록된 개체와 비교하여 동일 개체 여부를 판정한다 | 시나리오 3, 4 |
| F4 | 등록되지 않은 개체를 거절한다 | 시나리오 4 사례 B |
| F5 | 등록 사진 3~5장만으로 새 개체를 등록한다 | 시나리오 1 |
| F6 | 한 가정에 함께 사는 여러 개체를 서로 구분한다 | 문제 정의 (다견·다묘 가정) |

### 2.2 성능 요구사항

| 항목 | 목표치 | 출처 |
|---|---|---|
| 개체 식별 정확도 | 98.5% 이상 | PRD KPI |
| 오인식률(FAR) | 0.1% 이하 | PRD KPI |
| 접근 감지 후 토출까지 지연 | 1.2초 이내 | PRD KPI |
| 추론 속도 | 15 FPS 이상 | PRD KPI, 현장 조사 4-1 |

### 2.3 하드웨어 및 환경 제약

| 항목 | 내용 | 출처 |
|---|---|---|
| 연산 장치 | Rockchip RK3566 NPU (약 0.8 TOPS, INT8) | 현장 조사 4-2 |
| 원본 해상도 | 720p | 현장 조사 4-1 |
| 식별 입력 해상도 | 112×112 | 현장 조사 4-1 |
| 카메라 | 120° 광각, 설치 높이 25 cm, 야간 IR 전환 | 현장 조사 2-1~2-3 |
| 조명 | 150~400 Lux, 창문 역광, 플리커 존재 | 현장 조사 1-2~1-4 |
| 대상 개체 | 2마리 (검은 단모종 닥스훈트, 장모종 포메라니안) | 현장 조사 3-2 |
| 동작 특성 | 식사 중 고개 털기, 그릇 테두리에 의한 턱 가림 | 현장 조사 3-1, 3-3 |

15 FPS 조건에서 한 프레임의 처리 예산은 약 66 ms이며, 이 안에 전처리, 검출, 식별이 모두 완료되어야 한다.

## 3. 모델 구조 설계

### 3.1 2단계 구조 채택

개체 식별 방식으로 단일 분류 모델과 2단계(검출 + 임베딩 비교) 구조를 비교하였다.

| 비교 항목 | 단일 분류 모델 | 2단계 구조 |
|---|---|---|
| 새 개체 등록 | 개체가 추가될 때마다 재학습 필요 | 등록 사진의 임베딩 저장만으로 가능 |
| 미등록 개체 처리 | 학습한 클래스 중 하나로 강제 분류됨 | 유사도 임계값으로 거절 가능 |
| 가정별 적용 | 가정마다 별도 모델 학습 필요 | 모든 기기에 동일 모델 탑재 |
| 요구사항 충족 | F4, F5 미충족 | F1~F6 충족 |

단일 분류 모델은 F4와 F5를 충족하지 못하고 상용화 시 가정마다 모델을 학습해야 하므로, 2단계 구조를 채택하였다.

- 1단계: 얼굴 검출 및 특징점 추출 (F1, F2)
- 2단계: 얼굴을 임베딩(숫자 벡터)으로 변환한 후 등록 개체와 코사인 유사도 비교 (F3~F6)

2단계 모델은 특정 개체를 외우는 것이 아니라, 두 얼굴이 같은 개체인지를 판단하는 기준을 메트릭 러닝(Metric Learning)으로 학습한다. 따라서 학습에 포함되지 않은 개체에도 적용할 수 있다.

### 3.2 1단계 태스크 유형 선정

YOLO 계열 모델은 동일한 Backbone에 출력 Head를 바꾸어 다섯 가지 태스크를 지원한다. 각 태스크 유형의 적합성을 검토하였다.

| 유형 | 출력 | 검토 결과 |
|---|---|---|
| Detect | 경계 상자 | F2(특징점) 미충족. 대안 모델로 유지 |
| Pose | 경계 상자 + 특징점 | F1, F2를 단일 추론으로 충족. 채택 |
| Segment | 픽셀 단위 마스크 | 털 윤곽 정보는 식별에 불필요하며 연산량과 라벨링 비용 증가 |
| OBB | 회전 경계 상자 | 고개 기울기는 양 눈 특징점으로 보정 가능하여 불필요 |
| Classify | 이미지 단위 클래스 | 위치 정보가 없어 F1 미충족 |

특징점 라벨링 데이터가 부족하여 Pose 모델의 특징점 정확도가 기준에 미달하는 경우, Detect 모델(경계 상자만 출력)로 대체하고 얼굴 정렬 단계를 생략한다. 이 경우 정렬에 따른 식별 성능 향상분은 포기하지만 시스템 동작에는 지장이 없다.

### 3.3 특징점 정의

특징점은 다음 5개로 정의한다.

| 번호 | 특징점 | 용도 |
|---|---|---|
| 0 | 왼쪽 눈 | 얼굴 정렬(회전·크기 보정) |
| 1 | 오른쪽 눈 | 얼굴 정렬(회전·크기 보정) |
| 2 | 코 | 얼굴 정렬(중심 기준) |
| 3 | 왼쪽 귀 시작점 | 장모종의 얼굴 영역 보조 기준 |
| 4 | 오른쪽 귀 시작점 | 장모종의 얼굴 영역 보조 기준 |

- 양 눈과 코 좌표로 얼굴을 정면 기준으로 정렬(Affine 변환)한 후 2단계 모델에 입력하여, 고개 각도 변화가 임베딩에 미치는 영향을 줄인다.
- 입은 특징점에서 제외하였다. 급식 중에는 그릇 테두리에 의해 입과 턱이 가려지는 경우가 많아(현장 조사 3-3) 안정적으로 검출되지 않기 때문이다.

### 3.4 개체 판정 방식

한 가정에 등록된 개체(예: 초코, 보리)를 대상으로 다음 순서로 판정한다.

```
접근한 얼굴의 임베딩
 → 등록된 모든 개체의 기준 벡터와 코사인 유사도 계산
    예) 초코 0.91 / 보리 0.42
 → 조건 1: 1위 유사도 ≥ 유사도 임계값
 → 조건 2: 1위와 2위의 유사도 차이 ≥ 최소 차이값
 → 두 조건 모두 충족 시 1위 개체로 판정, 하나라도 미충족 시 판정 보류(다음 프레임 재시도)
```

- 비교 대상이 전체 동물이 아니라 해당 가정에 등록된 2~3마리로 한정되므로, 일반적인 얼굴 인식보다 판정이 쉽다.
- 조건 2는 서로 닮은 개체(같은 품종, 한배 형제)가 함께 사는 가정에서 개체 간 혼동을 막기 위한 조건이다.
- 임계값과 최소 차이값은 6.3.3절의 검증 절차로 결정한다.

### 3.5 체중 보조 판정

얼굴 인식 결과를 체중 정보로 교차 확인하여 오급식(FP)을 추가로 줄인다.

| 얼굴 판정 | 체중 확인 | 최종 판정 |
|---|---|---|
| 개체 A | 개체 A의 등록 체중 범위 이내 | 급식 |
| 개체 A | 개체 A의 등록 체중 범위 밖 | 판정 보류 |
| 판정 보류 | (무관) | 판정 보류 |

- 현장 대상 개체인 닥스훈트(약 5~10 kg)와 포메라니안(약 2~3 kg)은 체중 차이가 커서, 얼굴 인식이 오판하더라도 체중으로 대부분 걸러진다.
- 체중 범위는 등록 시 측정값을 기준으로 설정하고, 매 급식 시 측정값으로 갱신한다. 체중 기록은 건강 관리 데이터로도 활용한다.
- PRD의 로드셀은 사료 그릇 무게 측정용이므로, 반려동물 체중 측정을 위해 급식기 전면에 발판형 체중계를 추가해야 한다(7장 PRD 수정 제안).

### 3.6 가정별 적용 방식

상용화 시 각 가정의 반려동물에 맞추기 위해 가정마다 모델을 학습하지 않는다. 학습과 적용을 다음과 같이 분리한다.

| 단계 | 수행 위치 | 내용 |
|---|---|---|
| 공통 학습 | 제조사 (1회) | 다수의 동물 데이터로 얼굴 검출 및 개체 비교 능력을 학습하고, 모든 기기에 동일 모델 탑재 |
| 개체 등록 | 각 가정 기기 | 반려동물 사진 3~5장(주간·야간 각각 권장)을 촬영하여 임베딩 평균을 기준 벡터로 저장. 학습이 아닌 저장이므로 수 초 내 완료 |
| 기준 갱신 | 각 가정 기기 | 높은 유사도로 판정된 급식 장면의 임베딩을 기준 벡터에 소량씩 반영하여 털 길이, 나이에 따른 외형 변화를 반영 |
| 공통 모델 개선 | 제조사 (주기적) | 사용자 동의를 받은 인식 실패 사례를 수집하여 재학습하고 OTA로 배포 |

- 기준 갱신 시 오판된 장면이 반영되지 않도록, 유사도가 임계값보다 충분히 높은 경우에만 반영한다.
- 얼굴 임베딩은 기기 내부에만 저장하여 반려동물 사진이 외부로 전송되지 않도록 한다.
- PRD에서 클라우드 자동 재학습은 1차 범위에서 제외되어 있으므로, 공통 모델 개선은 수동 배치 학습으로 수행한다.

## 4. 모델 선정

### 4.1 1단계: 얼굴 검출·특징점 모델

#### 4.1.1 모델 구조

YOLO-pose는 다음 세 부분으로 구성된다.

| 구성 | 역할 | 학습 시 처리 |
|---|---|---|
| Backbone | 이미지에서 형태·질감 특징 추출 | COCO 사전학습 가중치 재사용 |
| Neck | 여러 크기의 특징을 결합 | COCO 사전학습 가중치 재사용 |
| Head | 경계 상자, 신뢰도, 특징점 출력 | 특징점 5개 규격으로 교체 후 새로 학습 |

#### 4.1.2 모델 크기 및 후보 비교

모델 크기는 n(nano)으로 선정하였다. 0.8 TOPS NPU에서 프레임당 66 ms 예산을 지키려면 s 이상의 크기는 검출 단계만으로 예산 대부분을 소모할 가능성이 높다.

| 후보 | 파라미터 수 | 연산량 (FLOPs, 640 기준) | 장점 | 검토 필요 사항 |
|---|---|---|---|---|
| YOLO11n-pose | 약 2.9M | 약 7.6 G | YOLOv8 대비 적은 연산량으로 높은 정확도 | RKNN 변환 시 미지원 연산 여부 |
| YOLOv8n-pose | 약 3.3M | 약 9.2 G | Rockchip rknn_model_zoo에 Pose 변환 예제가 있어 배포 위험이 낮음 | YOLO11 대비 낮은 정확도 |
| YOLO26n-pose | 확인 필요 | 확인 필요 | NMS 없는 출력 구조, 엣지 기기 지향 설계 | 최신 모델로 RKNN 툴킷 지원 여부 확인 필요 |

파라미터 수와 연산량은 Ultralytics 공개값이며 GPU 기준 성능이다. YOLO11n-pose를 1순위로 하되, 세 후보를 RK3566에서 INT8로 변환하여 측정한 처리 속도와 mAP50-95로 최종 선정한다.

#### 4.1.3 입력 해상도

입력 해상도는 320×320으로 설정한다. 카메라와 얼굴의 거리가 30 cm 이내로 얼굴이 화면에서 크게 촬영되므로, 작은 물체 검출 성능이 중요하지 않다. 연산량은 해상도의 제곱에 비례하므로 640×640 대비 약 1/4로 줄어든다.

### 4.2 2단계: 개체 식별 모델

| 항목 | 내용 |
|---|---|
| 모델 | MobileFaceNet |
| 파라미터 수 | 약 0.99M |
| 입력 | 112×112 (전처리 ⑦의 출력 규격과 동일) |
| 출력 | 128차원 임베딩 (L2 정규화) |
| 손실 함수 | ArcFace |
| 판정 | 등록 기준 벡터와의 코사인 유사도 (3.4절) |

MobileFaceNet은 112×112 입력에 최적화된 경량 얼굴 인식 CNN으로, PRD 기술 스택과 일치한다. ArcFace 손실은 같은 개체의 임베딩은 가깝게, 다른 개체의 임베딩은 일정한 각도 여유(margin)를 두고 멀어지도록 학습시켜, 미등록 개체 거절(F4)과 닮은 개체 구분(F6)에 유리하다.

### 4.3 처리 시간 배분

프레임당 66 ms 예산을 다음과 같이 배분하고, 기기 검증(6.5절)에서 실측값과 비교한다.

| 단계 | 목표 시간 |
|---|---|
| 전처리 ①~③ (Grayscale, 블러 판정, 왜곡 보정) | 10 ms 이하 |
| 1단계 YOLO-pose 추론 (320×320, INT8) | 30 ms 이하 |
| 전처리 ④~⑦ (크롭, CLAHE, 샤프닝, 정렬, 리사이즈) | 6 ms 이하 |
| 2단계 MobileFaceNet 추론 (112×112, INT8) | 10 ms 이하 |
| 유사도 비교 및 판정 | 2 ms 이하 |
| 여유 | 8 ms |

## 5. 학습 방법

### 5.1 학습 전략 개요

현장 데이터는 2마리 분량으로 규모가 작아 처음부터 학습하면 과적합이 발생한다. 따라서 두 모델 모두 사전학습 가중치에서 출발하는 전이학습(Transfer Learning)을 적용하고, 범용 데이터에서 현장 데이터로 범위를 좁혀가며 단계적으로 미세조정(Fine-tuning)한다.

```
[1단계 모델]
COCO-Pose 사전학습 가중치
 → A. Backbone 동결, Head만 학습 (공개 데이터)
 → B. 전체 미세조정 (공개 데이터 + 현장 데이터)

[2단계 모델]
ImageNet 사전학습 Backbone
 → A. 개체 식별 사전학습 (공개 반려동물 개체 데이터)
 → B. 미세조정 (공개 데이터 일부 + 현장 데이터)
```

### 5.2 학습 데이터 구성

#### 5.2.1 공개 데이터셋

| 용도 | 데이터셋 | 내용 |
|---|---|---|
| 1단계 얼굴 위치 | Oxford-IIIT Pet | 개·고양이 37개 품종, 머리 영역 경계 상자 포함 |
| 1단계 특징점 | Cat Dataset | 고양이 얼굴 특징점 9개 (눈, 입, 귀) |
| 1단계 특징점 | DogFLW | 강아지 얼굴 특징점 |
| 1단계 특징점 | AP-10K, StanfordExtra | 동물 전신 자세 특징점 (눈, 코 포함) |
| 2단계 개체 식별 | PetFace | 대규모 동물 개체별 얼굴 이미지 |
| 2단계 개체 식별 | DogFaceNet 데이터셋 | 강아지 개체별 얼굴 이미지 |

- 데이터셋마다 특징점 정의가 다르므로, 3.3절의 5개 특징점(양 눈, 코, 양 귀 시작점)으로 변환하여 통합한다. 해당 특징점이 없는 데이터는 그 특징점을 '보이지 않음'으로 표시한다.
- 공개 데이터셋 다수가 비상업(연구용) 라이선스이다. 과제 및 시제품에는 사용할 수 있으나, 상용 제품 출시 전 라이선스를 검토하고 필요 시 자체 수집 데이터로 대체한다.

#### 5.2.2 현장 데이터

| 항목 | 계획 |
|---|---|
| 대상 | 닥스훈트, 포메라니안 (2마리) + 미등록 개체(검증용) |
| 수집 횟수 | 개체별 촬영 세션 10회 이상 (주간·야간·역광 조건 분산) |
| 수집량 | 개체별 라벨링 완료 이미지 1,000장 이상 |
| 균형 | 두 개체의 이미지 수를 비슷하게 맞추어 클래스 불균형 방지 |

수집량은 초기 계획값이며, 조건별 검증(6.4절)에서 기준에 미달하는 조건의 데이터를 추가 수집한다.

### 5.3 현장 데이터 수집 조건

현장 조사에서 확인된 조건이 학습 및 검증 데이터에 고르게 포함되도록 수집한다.

| 조건 | 수집 방법 |
|---|---|
| 주간 RGB / 야간 IR | 동일 개체를 두 모드에서 모두 촬영 |
| 창문 역광 | 오전, 오후, 흐린 날로 구분하여 촬영 |
| 고개 털기 | 식사 중 연속 영상에서 프레임 추출. 흐린 프레임은 블러 필터 임계값 검증용으로 별도 보관 |
| 턱 가림 | 식사 중 고개를 숙인 장면 포함 |
| 미등록 개체 | 타 반려동물 및 공개 데이터 이미지. 거절 성능 검증용 |

### 5.4 라벨링 방법

현장 데이터는 AI 자동 라벨링 후 사람이 검수하는 방식으로 라벨링하여 작업 시간을 줄인다.

| 라벨 | 자동 라벨링 방법 | 검수 |
|---|---|---|
| 얼굴 경계 상자 | Grounding DINO 등 텍스트 기반 검출 모델에 "dog face" 입력 | 상자 위치 수정, 누락 추가 |
| 눈·코 특징점 | AP-10K로 학습된 동물 자세 모델(MMPose 등)로 예측 | 위치 수정 |
| 귀 시작점 | 자동 예측 대상 아님 | 직접 표시 |
| 개체 이름 | 영상 단위로 개체 이름을 한 번 지정하면 해당 영상의 전체 프레임에 적용 | 두 개체가 함께 찍힌 프레임 확인 |

- 라벨링 도구는 자동 라벨링과 검수 기능을 함께 제공하는 Roboflow 또는 CVAT를 사용한다.
- 1단계 모델의 1차 학습이 끝나면, 이 모델로 나머지 현장 데이터를 자동 라벨링하고 검수하는 방식으로 전환한다.

### 5.5 전처리와의 정합

학습 데이터에도 [prosss.md](prosss.md)의 전처리를 추론 시와 동일한 순서로 적용한다. 학습과 추론의 입력 분포가 다르면 실제 동작 시 정확도가 저하되기 때문이다. 전처리 파이프라인 내 모델 배치는 다음과 같다.

```
720p 프레임
 → ① Grayscale 채널 통일 (모델 입력 시 1채널을 3채널로 복제)
 → ② 블러 프레임 기각
 → ③ 광각 왜곡 보정
 → [1단계] YOLO-pose (320×320) : 얼굴 경계 상자 + 특징점 5개
 → ④ ROI 크롭 (+15% 확장)
 → ⑤ CLAHE → ⑥ 샤프닝
 → 특징점 기반 얼굴 정렬
 → ⑦ 112×112 리사이즈 · 정규화
 → [2단계] MobileFaceNet : 128차원 임베딩
 → 등록 기준 벡터와 코사인 유사도 비교 (3.4절) → 체중 보조 판정 (3.5절)
```

- 전처리 명세에는 검출 모델의 위치가 정의되어 있지 않다. ④ ROI 크롭에 경계 상자가 필요하므로 ③과 ④ 사이에 배치하였다.
- 특징점 기반 얼굴 정렬은 전처리 명세에 없는 단계로, Pose 모델의 출력을 활용하여 추가하였다.
- 공개 데이터는 컬러 이미지가 대부분이므로 Grayscale로 변환하여 학습한다. 주간 RGB와 야간 IR의 도메인 차이(Domain Gap)를 줄이는 효과가 있다.

### 5.6 데이터 증강

증강은 현장에서 실제로 발생하는 변화에 한정하여 적용한다. Mosaic 증강은 5.8절에서 별도로 다룬다.

| 증강 기법 | 설정 | 대응 현장 조건 |
|---|---|---|
| 밝기·감마 변화 | 밝기 ±40% | 역광, 조도 변화 |
| 약한 모션블러 | 커널 크기 3~7 | 블러 필터를 통과하는 수준의 흔들림 |
| 하단 영역 가림(Cutout) | 얼굴 하단 0~30% | 그릇 테두리에 의한 턱 가림 |
| 좌우 반전 | 확률 50% | 고개 방향 |
| 회전 | ±15° | 고개 기울기 |
| 색상(Hue)·채도 변화 | 적용 안 함 | 입력이 Grayscale이므로 불필요 |

- 좌우 반전 시 왼쪽과 오른쪽 특징점의 순서를 교환한다(`flip_idx: [1, 0, 2, 4, 3]`).
- 2단계 학습에도 같은 증강을 적용하되, 얼굴 정렬 이후 이미지이므로 회전 범위는 ±5°로 줄인다.

### 5.7 데이터 분할

| 세트 | 비율 | 용도 |
|---|---|---|
| 학습(Train) | 70% | 가중치 학습 |
| 검증(Validation) | 15% | 하이퍼파라미터 조정, 조기 종료, 임계값 결정 |
| 테스트(Test) | 15% | 최종 성능 평가 (학습 중 사용 금지) |

- 연속 영상에서 추출한 인접 프레임은 거의 동일하므로, 무작위로 분할하면 데이터 누수(Data Leakage)가 발생하여 검증 성능이 과대평가된다. 따라서 촬영 세션(날짜·시간대) 단위로 분할한다.
- 2단계 모델의 일반화 성능 평가를 위해, 공개 데이터 중 학습에 사용하지 않은 개체를 테스트 세트에 별도로 구성한다.

### 5.8 학습 설계 결정 요소

학습 설정은 데이터 조건(이미지 수, 도메인 거리)과 학습 환경(GPU VRAM)에서 출발하여, 모델 크기, 프리징, 해상도, 배치, 모자이크, 캐싱, AMP, 에폭 순으로 결정하였다.

#### 5.8.1 출발 조건

| 요소 | 이 프로젝트의 상황 | 학습 설계에 미치는 영향 |
|---|---|---|
| 이미지 수 | 공개 데이터 수천~1만 장 수준 + 현장 데이터 약 2,000장 (개체당 1,000장) | 소~중규모. 처음부터 학습하기에는 부족하여 전이학습 필수 |
| 도메인 거리 | 사전학습(COCO): 컬러 일상 사진, 사람 특징점 / 목표: 근거리 Grayscale·IR 반려동물 얼굴, 광각 왜곡 보정 영상 | 거리가 먼 편. 저수준 특징(윤곽, 질감)은 재사용 가능하나 고수준 특징과 Head는 다시 학습해야 함 |
| GPU VRAM | 학습 환경 Google Colab T4 (VRAM 16 GB) 기준 (가정) | 배치 크기, 해상도, AMP, 캐싱 설정의 상한을 결정 |

#### 5.8.2 결정 사항

| 요소 | 결정 | 근거 |
|---|---|---|
| 모델 크기 | n (nano) | 추론 기기(RK3566)의 속도 제약이 우선 기준. 또한 소규모 데이터에서는 작은 모델이 과적합 위험이 낮고 VRAM 사용량이 적음 |
| 프리징 | A 단계: Backbone 동결 (`freeze=11`, YOLO11의 Backbone은 0~10번 층) / B 단계: 동결 해제 | 데이터가 적고 도메인 거리가 멀다. 먼저 새로 만든 Head를 안정시킨 뒤 전체를 낮은 학습률로 조정해야 사전학습 특징을 보존하면서 새 도메인에 맞출 수 있음 |
| 해상도 | 320×320 (학습과 추론 동일) | 얼굴이 근거리에서 크게 촬영됨. 학습과 추론 해상도가 다르면 성능이 떨어지므로 추론 해상도와 맞춤 |
| 배치 | 64 | n 모델과 320 해상도는 VRAM 사용량이 작아 16 GB에서 큰 배치가 가능. 배치가 클수록 배치 정규화 통계가 안정됨 |
| 모자이크 | 사용 (확률 1.0), 마지막 10 에폭 해제 (`close_mosaic=10`) | 데이터가 적어 다양한 배경·배치 조합을 만드는 효과가 큼. 다만 이미지 4장을 합치면 얼굴이 작아져 실제 근거리 촬영과 달라지므로, 학습 후반에는 해제하여 실제 조건에 맞춤 |
| 캐싱 | RAM 캐싱 (`cache='ram'`), 메모리 부족 시 디스크 캐싱 | 320 해상도 기준 약 1만 장은 RAM에 올릴 수 있는 규모이며, 매 에폭마다 이미지를 다시 읽는 시간을 줄여 학습 속도가 향상됨. 전처리(①~③)는 캐싱 전에 미리 적용해 두어야 함 |
| AMP | 사용 (`amp=True`) | T4 GPU는 FP16 연산 가속을 지원하여 학습 속도가 빨라지고 VRAM 사용량이 줄어듦. 손실 값이 NaN이 되는 등 학습이 불안정하면 해제 |
| 에폭 | A 단계 50 / B 단계 100, 조기 종료 `patience=20` | 데이터가 적어 에폭을 많이 돌리면 과적합 위험이 있음. 상한을 두고 검증 mAP50-95가 20 에폭 동안 개선되지 않으면 중단 |

#### 5.8.3 기타 주요 설정

| 요소 | 결정 | 근거 |
|---|---|---|
| 학습률 | A 단계 0.01 / B 단계 0.001 | 전체 미세조정 시 학습률을 1/10로 낮추어 사전학습 특징 훼손 방지 |
| 옵티마이저 | SGD (momentum 0.937, weight decay 0.0005) | 전이학습에서 안정적인 수렴. weight decay로 과적합 억제 |
| 학습률 예열 | 3 에폭 (`warmup_epochs=3`) | 새로 초기화된 Head의 큰 기울기로 Backbone이 흔들리는 것을 방지 |
| 클래스 | 단일 클래스 (반려동물 얼굴) | 개체 구분은 2단계에서 수행 |
| 재현성 | 고정 시드 (`seed=0`, `deterministic=True`) | 후보 모델 비교 시 같은 조건에서 학습 |

### 5.9 1단계 학습 설정 (YOLO-pose)

5.8절의 결정 사항을 Ultralytics 학습 설정으로 정리하면 다음과 같다.

| 항목 | A. Head 학습 | B. 전체 미세조정 |
|---|---|---|
| 데이터 | 공개 데이터 | 공개 데이터 + 현장 데이터 |
| 시작 가중치 | `yolo11n-pose.pt` (COCO-Pose) | A 단계 결과 |
| 프리징 | `freeze=11` | 없음 |
| 에폭 | 50 | 100 |
| 배치 | 64 | 64 |
| 해상도 | 320 | 320 |
| 학습률 | 0.01 | 0.001 |
| 모자이크 | `mosaic=1.0`, `close_mosaic=10` | 동일 |
| 캐싱 | `cache='ram'` | 동일 |
| AMP | `amp=True` | 동일 |
| 조기 종료 | `patience=20` | 동일 |

```python
from ultralytics import YOLO

# A. Head 학습 (Backbone 동결)
model = YOLO("yolo11n-pose.pt")
model.train(data="pet_face_pose.yaml", imgsz=320, epochs=50, batch=64,
            freeze=11, lr0=0.01, optimizer="SGD", warmup_epochs=3,
            mosaic=1.0, close_mosaic=10, cache="ram", amp=True,
            patience=20, seed=0, deterministic=True)

# B. 전체 미세조정 (동결 해제, 학습률 1/10)
model = YOLO("runs/pose/train/weights/best.pt")
model.train(data="pet_face_pose_field.yaml", imgsz=320, epochs=100, batch=64,
            lr0=0.001, optimizer="SGD", warmup_epochs=3,
            mosaic=1.0, close_mosaic=10, cache="ram", amp=True,
            patience=20, seed=0, deterministic=True)
```

- 데이터 설정 파일에는 `kpt_shape: [5, 3]`과 `flip_idx: [1, 0, 2, 4, 3]`을 지정한다.
- 손실 함수는 경계 상자 위치 손실, 신뢰도 손실, 특징점 위치 손실의 합으로 구성된다(Ultralytics 기본 구성).

### 5.10 2단계 학습 설정 (MobileFaceNet)

2단계 모델도 같은 결정 요소로 설정하였다.

| 요소 | A. 개체 식별 사전학습 | B. 미세조정 | 근거 |
|---|---|---|---|
| 이미지 수 | 공개 데이터 수만 장 이상 (PetFace, DogFaceNet) | 공개 데이터 일부 + 현장 약 2,000장 | A는 대규모, B는 소규모 |
| 도메인 거리 | ImageNet → 반려동물 얼굴: 멂 | 공개 반려동물 얼굴 → 현장 IR·역광 얼굴: 가까움 | A는 전체 학습, B는 일부 동결로 충분 |
| 모델 크기 | MobileFaceNet (약 0.99M) | 동일 | 추론 기기 제약 |
| 프리징 | 없음 | 앞쪽 층 동결, 뒤쪽 층과 임베딩 층만 학습 | B는 도메인이 가깝고 개체 수가 적어 일부만 조정 |
| 해상도 | 112×112 | 112×112 | 전처리 ⑦ 및 추론 입력과 동일 |
| 배치 | 256 | 128 | 112 해상도의 경량 모델로 VRAM 여유가 큼. ArcFace는 배치가 클수록 한 번에 비교하는 개체가 많아져 학습이 안정됨 |
| 모자이크 | 사용 안 함 | 사용 안 함 | 정렬된 얼굴 한 장이 입력이므로 여러 이미지를 합치면 얼굴 구조가 깨짐 |
| 캐싱 | 디스크 캐싱 | RAM 캐싱 | A는 데이터가 커서 RAM 초과 가능, B는 RAM에 올릴 수 있는 규모 |
| AMP | 사용 | 사용 | 학습 속도 향상 및 VRAM 절감 |
| 에폭 | 30 | 20 | 조기 종료: 검증 세트 TAR@FAR 0.1%가 5 에폭 동안 개선되지 않으면 중단 |
| 학습률 | 0.1 (단계적 감소) | 0.001 | 미세조정 시 낮은 학습률 |
| 손실 함수 | ArcFace (scale 64, margin 0.5) | 동일 | 4.2절 |

- 현장 데이터는 개체가 2마리뿐이어서 이것만으로 미세조정하면 두 개체만 구분하도록 과적합되고, 처음 보는 개체를 구분하는 능력이 사라진다. 따라서 B 단계에서도 공개 데이터의 다른 개체들을 함께 섞어 학습한다.
- 현장 개체를 학습에서 제외하고 등록 기준 벡터 생성에만 사용하는 비교 실험도 함께 수행하여, 미세조정의 효과를 확인한다.

### 5.11 과적합 방지

| 방법 | 적용 |
|---|---|
| 전이학습 및 프리징 | 사전학습 가중치에서 시작하고 초기에는 Backbone을 동결 |
| 작은 모델 크기 | n 크기 모델로 데이터 대비 파라미터 수를 제한 |
| 데이터 증강 및 모자이크 | 5.6절, 5.8절 |
| 조기 종료 | 검증 성능이 개선되지 않으면 학습 중단 |
| 가중치 감쇠(Weight Decay) | 0.0005 |
| 데이터 혼합 | 2단계 미세조정 시 공개 데이터 개체를 함께 학습 |
| 학습 곡선 확인 | 에폭별 학습 손실과 검증 손실을 기록하여, 학습 손실은 감소하는데 검증 손실이 증가하는 구간을 과적합으로 판단 |

### 5.12 양자화 및 배포

```
PyTorch 모델 (.pt) → ONNX 변환 → RKNN-Toolkit2 INT8 양자화 (.rknn) → RK3566 NPU 추론
```

- 양자화 보정(Calibration) 데이터에는 주간, 야간, 역광 현장 이미지를 고르게 포함한다. 주간 이미지만 사용할 경우 야간 IR 입력에서 정확도 저하가 발생할 수 있다.
- 양자화 후 정확도 하락이 1%p를 초과하면 양자화 인식 학습(QAT)을 적용한다.
- 본 절의 설정값(5.8~5.10절)은 초기 설정값이며, 검증 세트 결과와 실제 GPU 메모리 사용량에 따라 조정한다.

## 6. 검증 계획

### 6.1 검증 체계

검증은 객체 검출 모델의 표준 평가 지표인 신뢰도, 임계값, IoU, 정답(TP)·오답(FP), 정밀도, 재현율, AP·mAP를 기준으로 한다. 1단계(얼굴 검출)는 이 지표를 그대로 적용하고, 2단계(개체 식별)는 같은 개념을 급식 판정 결과에 대응시켜 적용한다.

| 용어 | 정의 | 1단계: 얼굴 검출 | 2단계: 개체 식별 |
|---|---|---|---|
| 신뢰도 | 모델이 출력한 예측의 확신 정도 | 경계 상자가 얼굴일 확률 | 등록 개체와의 코사인 유사도 |
| 임계값 | 예측을 인정하는 최소 기준 | 신뢰도 기준 (초기값 0.5) | 유사도 기준 (6.3.3절에서 결정) |
| IoU | 예측 상자와 정답 상자의 겹침 비율 (교집합 / 합집합) | 정답 판정 기준 | 해당 없음 |
| 정답(TP) | 올바른 예측 | 얼굴을 정확한 위치에서 검출 | 등록 개체를 해당 개체로 판정 (정상 급식) |
| 오답(FP) | 잘못된 예측 | 얼굴이 아닌 영역을 얼굴로 검출 | 다른 개체를 등록 개체로 판정 (오급식) |
| 놓침(FN) | 있어야 할 대상을 예측하지 못함 | 얼굴을 검출하지 못함 | 등록 개체를 인식하지 못함 (미급식) |
| 정밀도 | TP / (TP + FP) | 검출 결과 중 실제 얼굴의 비율 | 급식 판정 중 올바른 판정의 비율 |
| 재현율 | TP / (TP + FN) | 실제 얼굴 중 검출된 비율 | 등록 개체의 접근 중 인식된 비율 |
| AP | 정밀도-재현율 곡선 아래 면적 | 얼굴 클래스의 검출 성능 | 유사도 임계값 전 구간의 판정 성능 |
| mAP | 클래스별(또는 IoU 기준별) AP의 평균 | mAP50, mAP50-95 | 해당 없음 |

검증은 오프라인(테스트 세트), 기기(RK3566), 현장의 순서로 진행하며, 이전 단계의 기준을 충족한 경우에만 다음 단계로 진행한다.

### 6.2 1단계 검증: 얼굴 검출

#### 6.2.1 채점 기준

테스트 세트의 각 예측 상자는 다음 기준으로 채점한다.

| 판정 | 조건 |
|---|---|
| 정답(TP) | 신뢰도 ≥ 임계값이고, 정답 상자와의 IoU ≥ 0.5 |
| 오답(FP) | 신뢰도 ≥ 임계값이지만 IoU < 0.5이거나, 얼굴이 아닌 영역(사료 그릇, 장난감 등)을 검출 |
| 놓침(FN) | 정답 상자에 대응하는 예측이 없음 |

#### 6.2.2 평가 지표

| 지표 | 산출 방법 | 목표 |
|---|---|---|
| 정밀도 | TP / (TP + FP) | 0.95 이상 |
| 재현율 | TP / (TP + FN) | 0.98 이상 |
| AP50 | IoU 0.5 기준 정밀도-재현율 곡선 아래 면적 | 후보 모델 간 비교 |
| mAP50-95 | IoU 기준을 0.50부터 0.95까지 0.05 간격으로 바꾸어 구한 AP의 평균 | 후보 모델 간 비교 |
| 특징점 AP | IoU 대신 OKS(특징점 위치 유사도)로 채점한 AP | 얼굴 정렬 품질 확인 |

- 정밀도와 재현율 목표는 PRD에 정의되어 있지 않아 본 보고서에서 설정한 값이며, 6.2.3절의 재현율 우선 원칙을 반영하였다.
- 검출 클래스가 '반려동물 얼굴' 하나이므로 클래스 기준의 mAP는 AP와 같다. 따라서 후보 모델 비교에는 IoU 기준을 평균한 mAP50-95를 사용한다.
- mAP50-95는 상자 위치의 정밀도까지 반영한다. 상자가 정확해야 이후 ROI 크롭(전처리 ④)에서 얼굴이 잘리지 않으므로, 이 값은 2단계 식별 성능에도 영향을 준다.

#### 6.2.3 신뢰도 임계값 결정

1단계는 재현율을 우선한다.

- 얼굴을 놓치면(FN) 2단계로 넘어갈 기회 자체가 사라진다.
- 얼굴이 아닌 영역을 검출(FP)하더라도 2단계에서 등록 개체와의 유사도가 낮아 거절된다.

검증 세트에서 신뢰도 임계값을 0.05 간격으로 바꾸어 정밀도와 재현율을 산출하고, 정밀도 0.95 이상을 유지하는 범위에서 재현율이 가장 높은 값을 최종 임계값으로 정한다.

### 6.3 2단계 검증: 개체 식별

#### 6.3.1 채점 기준

급식기 앞에 접근한 대상과 모델의 판정 결과를 다음과 같이 채점한다. 예시는 등록 개체 '초코'와 '보리'가 있는 가정을 기준으로 한다.

| 실제 대상 | 판정 결과 | 채점 | 급식 결과 |
|---|---|---|---|
| 초코 | 초코 | 정답(TP) | 정상 급식 |
| 보리 또는 미등록 동물 | 초코 | 오답(FP) | 오급식 |
| 초코 | 거절 | 놓침(FN) | 미급식 (다음 프레임에서 재시도) |
| 미등록 동물 | 거절 | 정상 거절(TN) | 정상 차단 |

#### 6.3.2 평가 지표

| 지표 | 산출 방법 | 의미 | 목표 |
|---|---|---|---|
| 정밀도 | TP / (TP + FP) | 급식 판정이 올바른 비율 | 0.999 이상 (본 보고서 설정) |
| 재현율 | TP / (TP + FN) | 등록 개체가 인식된 비율 | 0.985 이상 (PRD 식별 정확도) |
| 오인식률(FAR) | FP / (FP + TN) | 다른 개체의 접근 중 잘못 승인된 비율 | 0.1% 이하 (PRD) |
| AP | 유사도 임계값 전 구간의 정밀도-재현율 곡선 아래 면적 | 임계값과 무관한 모델 자체의 식별 성능 | 후보 모델 간 비교 |

PRD의 오인식률(FAR)은 다른 개체의 시도 중 잘못 승인된 비율로 정의되므로 정밀도와 분모가 다르다. 두 지표를 함께 보고한다.

#### 6.3.3 유사도 임계값 결정

2단계는 정밀도를 우선한다.

- 오답(FP)은 처방식 사료가 다른 개체에게 지급되는 상황으로, 건강 악화로 이어질 수 있다.
- 놓침(FN)은 반려동물이 급식기 앞에 수 초간 머무는 동안 다음 프레임에서 다시 인식할 수 있다.

PRD는 인증 기준을 유사도 85% 이상으로 명시하였으나, 유사도 분포는 모델과 데이터에 따라 달라지므로 고정값을 그대로 적용하지 않는다. 결정 절차는 다음과 같다.

1. 검증 세트에서 유사도 임계값을 0.01 간격으로 바꾸어 정밀도, 재현율, 오인식률을 산출한다.
2. 오인식률 0.1% 이하(정밀도 우선)를 만족하는 임계값 중 재현율이 가장 높은 값을 선택한다.
3. 1위 개체와 2위 개체의 유사도 차이가 일정 값 미만이면 판정을 보류하는 조건을 함께 적용한다. 등록 개체가 2마리 이상인 가정에서 개체 간 혼동을 줄이기 위함이다.
4. 확정된 임계값을 PRD의 인증 기준에 반영한다.

| INT8 양자화 후 2단계 정밀도·재현율 하락 | 1%p 이내 |

| 장시간 연속 동작 | 발열에 따른 처리 속도 저하 여부 확인 |

### 6.6 현장 검증

- PRD의 측정 방법에 따라 등록 개체 1,000회 접근 테스트를 주간과 야간을 포함하여 수행한다.
- 각 접근을 6.3.1절의 기준(TP, FP, FN, TN)으로 채점하여 정밀도, 재현율, 오인식률을 산출한다.
- 오답(FP)과 놓침(FN) 사례의 영상은 저장하여 원인을 분류하고, 다음 학습 데이터로 활용한다.

## 8. 결론

반려동물 개체 인식 급식기의 AI 모델은 YOLO-pose 기반 얼굴 검출·특징점 모델과 MobileFaceNet 기반 개체 식별 모델의 2단계 구조로 설계하였다. 2단계 구조는 재학습 없는 개체 등록과 미등록 개체 거절을 가능하게 하며, Pose 태스크는 검출과 얼굴 정렬에 필요한 특징점을 단일 추론으로 제공한다.

한 가정의 개체 판정은 등록 개체 간 유사도 비교로 수행하고, 체중 정보로 교차 확인하여 오급식을 줄인다. 상용화 시에는 가정마다 모델을 학습하지 않고, 공통 모델에 개체 사진 3~5장을 등록하는 방식으로 적용한다.

RK3566 NPU의 연산 제약과 근거리 촬영 조건을 고려하여 n 크기 모델과 320×320 입력을 선정하였다. 학습은 이미지 수와 도메인 거리를 기준으로 프리징과 에폭을, GPU VRAM을 기준으로 배치, 캐싱, AMP를 결정하였으며, 소규모 현장 데이터의 한계는 사전학습 가중치 기반 전이학습과 단계적 미세조정으로 보완한다.

검증은 IoU 기반 채점과 정밀도, 재현율, AP·mAP 지표로 수행한다. 1단계 얼굴 검출은 얼굴을 놓치지 않도록 재현율을 우선하고, 2단계 개체 식별은 오급식을 막기 위해 정밀도를 우선하여 각 단계의 임계값을 결정한다.
