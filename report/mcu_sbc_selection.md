# SBC·MCU 부품 선정 보고서: AI 처리 장치와 제어 장치

- 과제명: 반려동물 개체 인식 자동 급식기 (PawFeeder AI)
- 문서 구분: SBC·MCU 부품 선정 보고서
- 작성일: 2026-10-16
- 버전: v1.0

## 요약

**선택: SBC는 Rockchip RK3566, MCU는 Espressif ESP32-S3**

| 구분 | 1순위 (선택) | 점수 | 다른 후보 (점수) |
|---|---|---|---|
| **SBC** (AI 담당) | **RK3566** | **88** | RK3588 (80), Raspberry Pi 5 (71), Jetson Orin Nano (68) |
| **MCU** (제어 담당) | **ESP32-S3** | **95** | RP2040 (72), STM32F411 (70), ATmega328P (43) |

```
           ┌──────────────────────────┐   UART    ┌──────────────────────────┐
카메라 ──▶ │ SBC: RK3566 (AI 담당)    │ ◀───────▶ │ MCU: ESP32-S3 (제어 담당) │ ──▶ 모터·센서·LCD
           │ 얼굴 인식, 서버 통신      │  명령/결과 │ 정량 토출, 덮개, 무게 측정 │
           └──────────────────────────┘           └──────────────────────────┘
```

- **RK3566:** AI 전용 칩(NPU)과 카메라 단자를 갖추면서도 전력과 가격이 낮아, 가정용 급식기에 가장 균형이 맞습니다.
- **ESP32-S3:** 필요한 핀과 통신 단자가 넉넉하고, Wi-Fi·BLE가 내장되어 나중에 구성을 바꾸기도 쉽습니다.

## 1. 개요

### 1.1 목적

급식기의 두뇌 역할을 하는 처리 장치를 고릅니다. AI 인식을 맡을 **SBC**와 실시간 제어를 맡을 **MCU**를 각각 후보 4종과 비교해 선택합니다.

### 1.2 용어

| 용어 | 쉬운 설명 |
|---|---|
| **SBC** (Single Board Computer) | 기판 한 장에 CPU, RAM, 저장장치, 네트워크가 있는 작은 컴퓨터. Linux가 돌아감 |
| **MCU** (Micro Controller Unit) | CPU, 메모리, 입출력 핀이 칩 하나에 들어간 제어용 칩. OS 없이 정확한 타이밍으로 동작 |
| **NPU** | AI 계산 전용 칩. TOPS(초당 1조 번 연산) 단위로 성능을 표시 |
| **MIPI CSI-2** | 카메라 영상을 고속으로 받는 단자 |
| **SoM** | SBC를 작은 모듈로 만들어 제품 기판에 꽂아 쓰는 형태. 양산 제품에 주로 사용 |
| **GPIO / UART / I2C / SPI / PWM** | MCU가 센서, 모터, 화면과 연결할 때 쓰는 핀과 통신 방식 |

### 1.3 이 제품이 처리 장치에 요구하는 것

| 요구 | 내용 | 출처 |
|---|---|---|
| 얼굴 인식 | YOLO11n-pose + MobileFaceNet 2개 모델을 기기 안에서 15 FPS 이상 | PRD, 모델 설계 보고서 |
| 카메라 | 2MP RGB-IR 글로벌 셔터 카메라 (MIPI CSI-2) | PRD |
| 오프라인 | 인터넷이 끊겨도 인식과 급여 | PRD |
| 실시간 제어 | 스텝 모터 펄스, 서보, 로드셀 측정 | 하드웨어 부품 보고서 |
| 연결 핀 | MCU에 핀 24개 (I2C, SPI, UART 2개, PWM, GPIO) | 하드웨어 부품 보고서 6.5절 |
| 가정용 제품 | 12V 4A 어댑터 하나로 동작, 저발열, 합리적 원가 | 하드웨어 부품 보고서 |
| 소프트웨어 | Linux, NCNN, Docker 컨테이너 | 추론 엔진·컨테이너 보고서 |

## 2. 왜 SBC와 MCU를 함께 쓰는가

| 구성 | 문제 |
|---|---|
| MCU만 사용 | AI 전용 칩이 없어 얼굴 인식이 느리고, MIPI 카메라를 연결할 수 없음 |
| SBC만 사용 | Linux 때문에 모터 펄스 타이밍이 흔들리고, AI 쪽이 멈추면 모터와 덮개도 같이 멈춤 |
| **SBC + MCU** | SBC가 "누구인지" 판단하고, MCU가 "정확히 25g"을 실행. 각자 잘하는 일을 맡음 |

사람에 비유하면 SBC는 생각하는 **뇌**, MCU는 반사적으로 움직이는 **척수**입니다.

## 3. SBC 선정

### 3.1 후보

| 항목 | **RK3566** | RK3588 | Raspberry Pi 5 | Jetson Orin Nano |
|---|---|---|---|---|
| 만든 곳 | Rockchip | Rockchip | Raspberry Pi | NVIDIA |
| CPU | ARM Cortex-A55 4코어 | Cortex-A76 4코어 + A55 4코어 | Cortex-A76 4코어 | Cortex-A78AE 6코어 |
| AI 가속 | NPU 약 0.8 TOPS + Mali GPU | NPU 약 6 TOPS + Mali GPU | NPU 없음 (별도 AI 보드 추가 필요) | GPU 기반, 수십 TOPS |
| 카메라 단자 | MIPI CSI-2 | MIPI CSI-2 | MIPI CSI-2 | MIPI CSI-2 |
| 전력 | 낮음 | 중간 | 중간 | 높음 |
| 가격 | 낮음 | 중간 | 낮음~중간 | 높음 |
| 양산용 모듈 | 있음 (SoM 다수) | 있음 | 있음 (Compute Module) | 있음 |

### 3.2 선정 기준

| 기준 | 비중 | 확인 내용 |
|---|---|---|
| AI 성능 | 25% | 얼굴 인식 모델 2개를 15 FPS 이상으로 돌릴 수 있는가 |
| 전력·발열 | 20% | 12V 4A 어댑터, 밀폐된 급식기 안에서 열을 감당할 수 있는가 |
| 가격 | 20% | 가정용 급식기 원가에 맞는가 |
| 카메라 연결 | 15% | MIPI 글로벌 셔터 카메라를 바로 연결할 수 있는가 |
| 소프트웨어 | 10% | Linux, NCNN, Docker를 쓸 수 있는가 |
| 크기·양산 | 10% | 작은 모듈로 제품에 넣을 수 있는가 |

### 3.3 점수 (5점 만점 × 비중 → 100점 환산)

| 기준 (비중) | **RK3566** | RK3588 | Raspberry Pi 5 | Jetson Orin Nano |
|---|---|---|---|---|
| AI 성능 (25%) | 3 | 5 | 2 | 5 |
| 전력·발열 (20%) | **5** | 3 | 3 | 2 |
| 가격 (20%) | **5** | 3 | 4 | 1 |
| 카메라 연결 (15%) | 5 | 5 | 5 | 5 |
| 소프트웨어 (10%) | 4 | 4 | 5 | 5 |
| 크기·양산 (10%) | 5 | 4 | 4 | 3 |
| **합계** | **88** | **80** | **71** | **68** |

### 3.4 결과: RK3566

**고른 이유**
1. **필요한 만큼의 AI 성능:** 우리 모델은 작은 크기(nano, 112×112)라서, NPU 0.8 TOPS와 Mali GPU로 목표 속도를 낼 수 있는 수준입니다.
2. **낮은 전력과 발열:** 5V 최대 약 2A로, 밀폐된 급식기 안에 넣어도 부담이 적습니다.
3. **낮은 가격:** 고성능 칩보다 저렴해서 가정용 제품 원가에 맞습니다.
4. **양산이 쉬움:** RK3566을 쓴 작은 모듈(SoM)이 여러 회사에서 나와 있어, 시제품 보드에서 양산 모듈로 옮기기 쉽습니다.

**다른 후보를 고르지 않은 이유**

| 후보 | 이유 |
|---|---|
| RK3588 | AI 성능은 가장 좋지만 이 제품에는 과하고, 가격과 발열이 큼. **RK3566으로 속도가 부족할 때의 업그레이드 후보**로 둠 |
| Raspberry Pi 5 | 자료는 가장 많지만 AI 전용 칩이 없어 별도 AI 보드를 추가해야 하고, 그만큼 비용과 공간이 늘어남 |
| Jetson Orin Nano | AI 성능은 최고지만 가격과 전력이 가정용 급식기에 비해 너무 큼 |

## 4. MCU 선정

### 4.1 후보

| 항목 | **ESP32-S3** | RP2040 | STM32F411 | ATmega328P |
|---|---|---|---|---|
| 만든 곳 | Espressif | Raspberry Pi | STMicroelectronics | Microchip (Arduino Uno) |
| CPU | 32비트 2코어 240MHz | 32비트 2코어 133MHz | 32비트 1코어 100MHz | 8비트 16MHz |
| RAM | 512KB (+외부 PSRAM) | 264KB | 128KB | 2KB |
| 사용 가능 핀 | 약 36개 (모듈 기준) | 30개 | 약 36개 이상 | 약 20개 |
| UART 개수 | 3 | 2 | 3 | 1 |
| 무선 | Wi-Fi + BLE 내장 | 없음 (Pico W는 Wi-Fi 추가) | 없음 | 없음 |
| 동작 전압 | 3.3V | 3.3V | 3.3V | 5V |

### 4.2 선정 기준

| 기준 | 비중 | 확인 내용 |
|---|---|---|
| 핀·통신 단자 | 25% | 핀 24개와 UART 2개(RK3566 연결, 모터 드라이버 설정)를 모두 연결할 수 있는가 |
| 처리 성능 | 20% | 모터 펄스, 센서 측정, LCD 표시를 동시에 처리할 수 있는가 |
| 메모리 | 15% | LCD 화면 데이터와 급여 로직을 담을 수 있는가 |
| 무선 확장성 | 15% | 나중에 SBC 없이 단독 구성으로 바꿀 수 있는가 |
| 개발 편의·자료 | 15% | 예제와 자료가 많고 개발 도구가 쉬운가 |
| 가격 | 10% | 저렴한가 |

### 4.3 점수 (5점 만점 × 비중 → 100점 환산)

| 기준 (비중) | **ESP32-S3** | RP2040 | STM32F411 | ATmega328P |
|---|---|---|---|---|
| 핀·통신 단자 (25%) | **5** | 4 | 5 | 2 |
| 처리 성능 (20%) | **5** | 3 | 4 | 1 |
| 메모리 (15%) | **5** | 4 | 3 | 1 |
| 무선 확장성 (15%) | **5** | 2 | 1 | 1 |
| 개발 편의·자료 (15%) | 4 | 4 | 3 | 5 |
| 가격 (10%) | 4 | 5 | 4 | 4 |
| **합계** | **95** | **72** | **70** | **43** |

### 4.4 결과: ESP32-S3

**고른 이유**
1. **핀과 통신 단자가 넉넉함:** 필요한 핀 24개와 UART 2개를 모두 연결하고도 여유가 있습니다.
2. **2코어 240MHz:** 한 코어는 모터와 센서, 다른 코어는 LCD와 통신에 나눠 쓸 수 있습니다.
3. **Wi-Fi·BLE 내장:** 지금은 무선을 RK3566이 맡아서 꺼 두지만, 원가를 줄이려고 SBC 없이 ESP32-S3 단독 구성으로 바꿀 때 그대로 쓸 수 있습니다.
4. **자료가 많음:** Arduino, ESP-IDF로 개발할 수 있고, 모터 드라이버(TMC2209), HX711, LCD(ST7789) 예제가 풍부합니다.

**다른 후보를 고르지 않은 이유**

| 후보 | 이유 |
|---|---|
| RP2040 | 저렴하고 모터 펄스 생성(PIO)에 강하지만, 무선이 없고 UART가 2개뿐이라 여유가 없음 |
| STM32F411 | 타이머와 모터 제어 성능은 좋지만 무선이 없고 개발 난도가 높음 |
| ATmega328P | 자료는 가장 많지만 RAM 2KB, UART 1개로 이 제품의 연결을 감당할 수 없음 |

## 5. 선정 결과와 연결 구성

### 5.1 최종 구성

| 구분 | 선택 | 전압 | 전류 (평상시 / 최대) | 맡는 일 |
|---|---|---|---|---|
| SBC | RK3566 (보드 → 양산 시 SoM) | 5V | 0.5~1A / 2A | 카메라, AI 인식(NCNN), Wi-Fi·BLE, 컨테이너 |
| MCU | ESP32-S3-WROOM-1 | 3.3V | 40~100mA / 250mA | 모터, 서보, 로드셀, 거리 센서, LCD, 버튼 |

### 5.2 둘 사이 연결

| 항목 | 내용 |
|---|---|
| 통신 방식 | UART (TX, RX 2선) |
| 주고받는 것 | SBC → MCU: "덮개 열기", "25g 토출" / MCU → SBC: "토출 완료 24.8g", 센서 상태 |
| 안전 동작 | SBC가 응답하지 않으면 MCU가 스스로 덮개를 닫고 모터를 멈춤 |

### 5.3 시제품용 보드 예시

RK3566은 칩 이름이므로, 시제품에는 이 칩을 쓴 SBC 보드를 사용합니다. 예를 들어 Radxa ROCK 3C, Orange Pi 3B 같은 보드가 있습니다. 양산할 때는 같은 칩의 작은 모듈(SoM)을 제품 기판에 넣습니다. ESP32-S3는 시제품과 양산 모두 같은 모듈(ESP32-S3-WROOM-1)을 씁니다.

## 6. 고려사항

| 항목 | 내용 | 대응 |
|---|---|---|
| AI 속도 | RK3566의 성능으로 15 FPS가 실제로 나오는지 확인 필요 | 실측 후 부족하면 NPU 가속(RKNN) 추가, 그래도 부족하면 RK3588로 교체 |
| 점수의 근거 | 점수는 공식 사양과 일반적인 사용 사례로 매긴 것 | 시제품 보드로 속도, 전력, 발열을 직접 측정해 확인 |
| 발열 | 급식기 내부가 밀폐되어 있음 | SBC에 방열판, 사료통과 떨어진 위치에 배치 |
| 부품 수급 | 특정 보드가 단종될 수 있음 | 같은 칩을 쓰는 보드·모듈이 여러 회사에 있는 점을 활용 |
| 원가 절감 | SBC + MCU 구성은 부품이 2개 | 성능 목표를 낮출 수 있다면 ESP32-S3 단독 구성도 가능 (카메라 사양 하향 필요) |

## 7. 결론

1. AI 처리 장치(SBC)는 **RK3566**(88점), 실시간 제어 장치(MCU)는 **ESP32-S3**(95점)를 선택합니다.
2. RK3566은 AI 전용 칩과 카메라 단자를 갖추면서 **전력·발열·가격이 가장 낮아** 가정용 급식기에 가장 균형이 맞습니다.
3. ESP32-S3는 **핀과 통신 단자가 넉넉하고 Wi-Fi·BLE가 내장**되어, 지금 구성과 나중의 단독 구성 모두에 대응할 수 있습니다.
4. 둘은 UART로 연결하고, SBC가 판단하고 MCU가 실행하는 구조로 역할을 나눕니다.
5. 시제품 보드로 AI 속도와 발열을 측정해, 부족하면 RKNN 가속이나 RK3588로 보완합니다.
