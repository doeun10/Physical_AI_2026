1. 문제 정의 (Problem Statement)
•	현재 문제: 다견/다묘 가정 및 개별 맞춤 사료(처방식, 연령별 사료) 급여가 필요한 환경에서, 기존 사료 급식기는 특정 개체를 식별하지 못해 타 반려동물의 사료 섭취, 오급여로 인한 건강 악화, 식사량 미달/초과 관찰의 어려움이 발생함.
•	기존 방식의 한계:
o	타이머/단순 중량 제어 방식: 시간/양 제어는 가능하나 '누가' 먹는지 구분 불가능.
o	RFID/마이크로칩 인식 방식: 목걸이 태그 착용 필수(분실/거부감 문제), 센서 접근 각도에 따른 인식율 저하, 하드웨어 부품 추가에 따른 원가 상승.
•	핵심 가치: 카메라 visual 인식 기반의 100% 비접촉식 개체 식별을 통해 targeted 사료를 정량 자동 지급하고, 개체별 정확한 섭취 데이터를 자동 기록하여 건강 관리를 보조함.
•	AI 도입 이유: 반려동물은 표정, 털의 질감, 고개 각도 및 조명 환경 변화에 따른 변동성이 크므로, 단순 센서/기하학적 조건 기반 알고리즘으로는 개체 식별이 불가능함. Edge 단에서 경량화된 Deep Learning 기반 Face Detection/Recognition 모델 적용이 필수적임.
2. 사용자 시나리오 (User Scenario)
1.	설치 및 등록 (Setup & Enrollment): 사용자가 급식기를 식사 장소에 위치시키고 전원을 연결한다. 전용 인프라 앱/인터페이스를 통해 반려동물의 등록용 얼굴 사진 3~5장을 등록(가정)하고 개체별 급여 스케줄(사료량, 시간)을 설정한다.
2.	데이터 수집 (Data Collection): 급식기 전면에 탑재된 Wide-angle 카메라와 ToF/PIR 센서가 접근하는 물체를 감지한다. 접근 거리가 30cm 이내로 들어오면 카메라가 프레임 데이터를 수집하기 시작한다.
3.	분석 수행 (AI Analysis): Edge AI 모듈(MCU/NPU)이 수집된 비디오 프레임에서 1) 동물 감지(Bounding Box) -> 2) 얼굴 Keypoint 추출 -> 3) 등록된 개체 Feature Vector와의 매칭 유사도(Cosine Similarity) 계산을 수행한다.
4.	판단 결과 생성 (Decision Making):
o	사례 A (인증 성공): 등록된 개체 'A'로 판정(유사도 85% 이상)되고, 급여 가능 시간대일 경우 해당 개체의 급여 명령 생성.
o	사례 B (인증 실패/타 개체): 등록되지 않은 개체이거나 급여 대상이 아닐 경우 급식구 닫힘 유지 및 접근 경고 로직 생성.
5.	장치 제어 (Actuation): 판단 결과에 따라 서보 모터가 사료 출구 도어를 개방하고, 스텝 모터가 설정된 수치(예: 25g)만큼 사료 추출 디스펜서를 회전 구동한다. 로드셀 센서가 사료 그릇의 중량 변화를 실시간 피드백하여 정확한 정량을 지급한다.
6.	결과 확인 및 후속 행동 (Verification & Logging): 식사 완료 후 개체가 이탈하면 잔여 사료 중량을 측정하여 '실제 섭취량 = 지급량 - 잔여량' 데이터를 생성한다. 이 데이터는 MQTT를 통해 서버 및 대시보드로 전송되며, 사용자는 푸시 알림을 받고 일간/월간 섭취 그래프를 확인한다.

5. 개발 범위 / 비범위 (Scope)
개발 범위 (In Scope)
1.	실시간 이미지 기반 개체 인식: Edge 단에서의 반려동물 얼굴 Detection 및 Face Recognition Pipeline 구축.
2.	정밀 사료 토출 모터 제어: 로드셀 센서 Feedback Loop 기반 사료 정량 토출 구동 제어 로직.
3.	Edge-to-Cloud 동기화: 급여 이벤트, 섭취량, 사료 잔량, 장치 상태 로그의 MQTT 기반 Cloud 연동.
4.	사료 잔량 및 이상 상태 감지: optical/weight 센서 기반 사료 부족, 토출구 막힘(Jamming) 감지 및 예외 처리.
5.	관리자 웹 대시보드: 전체 기기 상태 모니터링, OTA(Over-The-Air) 펌웨어 업데이트 패키지 배포 시스템.
6.	로컬 오프라인 급여 모드: 네트워크 연결 단절 시에도 기기 내 저장된 스케줄 및 Edge AI 기반으로 급여를 수행하는 Safe-fail 로직.
7.	기기 이벤트 로그 저장: 장치별 동작 로그, 인식 실패 로그, 섭취 이력 데이터 생성 및 최소 1년 보존 DB 구성.
개발 제외 범위 (Out of Scope)
1.	음성 인식 및 음성 합성 기능: 음성 명령을 통한 사료 지급 기능 제외 (스피커를 통한 단순 녹음음 재생은 H/W 차원에서만 대응).
2.	네이티브 B2C 모바일 앱 직접 개발: 본 PRD는 HW/Edge/Server/Admin 중심 구축이며, B2C 앱은 기존 서비스 API 연동으로 대체 (가정).
3.	클라우드 상의 딥러닝 자동 재학습(Auto-ML) 파이프라인: 수집된 이미지를 기반으로 클라우드에서 자동으로 모델을 재학습하고 배포하는 MLOps 자동화 시스템은 1차 스코프에서 제외 (수동 바치 학습으로 대체).
4.	다국어 및 글로벌 규제(CE/FCC 외) 지원: 1차 출시 지역은 대한민국(KC 인증)으로 한정.
5.	사료 브랜드 자동 인식 기능: 사료 종류, 영양 성분을 이미지로 자동 파악하는 기능은 제외.
